# 設計

2026-11-16に作り直した設計です。この文書が、このリポジトリの設計の正本です。2026-11-11に書いた他の設計メモは、この文書と食い違う箇所ではこの文書を優先します。

料金と無料枠の上限は、2026-11-16に確認した値です。

## 目的

VS CodeとGitHubの公式ドキュメントのページを、読者が望んだときに日本語で読めるようにします。

- 読者は、原文のURLの先頭を書き換えるだけで、そのページの日本語訳を開けます。
- 日本語訳がまだ無いページは、読者がリクエストすると自動で訳され、少し待てば読めるようになります。
- どのページを訳すかは、読者のリクエストで決まります。こちらで事前に全ページを訳したり、訳すべきページを選んだりはしません。

VS Codeのドキュメントには、公式の日本語版がありません。GitHub Docsには公式の日本語版がありますが、書式が崩れたページや未訳のページがあります。どちらの場合も、読者が必要なページをこのサイトで読めます。

## 読者

自分と身近な人が読むことを前提にします。サイトは誰でも読める形で公開します。

## 予算

翻訳にはお金を使いません。

- 翻訳には、無料枠のあるAPIと、無償で使えるオープンウェイトのモデルだけを使います。
- 残高の入金や支払い方法の登録が条件になる無料枠は使いません。

ドメインの費用は未決です。

## リポジトリ

設計メモ、サイトのコード、訳文、翻訳とビルドのワークフローを、すべて公開リポジトリ`kkun84/ja-dev-docs`に置きます。

公開にするのは、GitHub Actionsの標準ランナーを、時間の上限なしに無料で使うためです。Actionsでサイトをビルドするので、サイトのコードも同じリポジトリに置きます。訳文も原文もCC BYの公開文書なので、公開して困る中身はありません。APIキーはGitHubのシークレットとCloudflareのシークレットに置きます。

設計メモだけを非公開のリポジトリに分ける案は採りません。非公開に残るのが設計メモだけになり、分ける利点が小さいためです。

## ホスティング

Cloudflare Workersの無料プランで公開します。Cloudflareが新規プロジェクトにはPagesよりWorkersを推奨しているためです。

- 静的ファイルは、Workersの静的アセットとして配信します。静的アセットへのリクエストは無料で、回数の上限もありません。
- 静的アセットにあるのは、日本語訳があるページだけです。それ以外のURLは、静的アセットに一致しないので、Workerが処理します。
- 無料プランの静的アセットは、1バージョンあたり2万ファイルが上限です。モデルごとの訳文は1ページのHTMLにまとめて入れ、ファイル数を訳したページの数と同じに抑えます。
- 翻訳リクエストと投票のAPIも、同じWorkerで動かします。データはD1に置きます。Workersの無料プランは、APIへのリクエストが1日10万回までです。
- Workerは、訳文もサイトの部品も読み込まない、手書きの小さなものにします(`worker/`)。AstroのアダプターでWorkerを作ると、全ページの訳文がWorkerのスクリプトに入り、数百ページでスクリプトの大きさの上限に届くためです。
- サイトは、GitHub Actionsでビルドし、Wranglerでデプロイします。

## フレームワーク

AstroのドキュメントテーマStarlightを使います。

- 日本語訳があるページは、ビルド時に静的に生成します。全モデルの訳文を、1ページのHTMLにまとめて入れます。
- 日本語訳が無いページと、翻訳リクエストと投票のAPIは、Astroではなく手書きのWorkerで返します。日本語訳が無いページは、Starlightとは別の単独のHTMLです。
- モデルの切り替えは、Starlightのページ部品を差し替えて実装します。既定以外の訳文は、検索の索引から外します。
- 検索は、Starlightが既定で使うPagefindです。日本語の分割に対応しています。
- GitHub Docsの独自のLiquidタグは、ビルドの前に自前のスクリプトで展開します。
- 各ページのURLは、訳文のフロントマターの`slug`で明示します。Astroは既定でファイル名を正規化し、`code.visualstudio.com`のような点を含むパスを書き換えてしまうためです。
- ページ内のリンクの書き換えは、描画した後のHTMLの`a`、`img`、`video`、`source`の属性に対して行います。Markdownの文字列に対して行うと、コードブロックの中の文字まで書き換えてしまうためです。
- VS Codeの画像と動画は、原文のリポジトリではGit LFSに入っていて`raw.githubusercontent.com`からは取れません。原文のサイトの配信元(`code.visualstudio.com/assets/...`)から読みます。
- サイドバーには、同じ節(VS Codeなら`docs/agents`、GitHub Docsなら`en/copilot`)の訳したページだけを並べます。全ページを並べると、1ページ足すたびに全ページのHTMLが変わり、サイトの大きさがページ数の2乗で増えるためです。全ページの一覧は`/list/`に置きます。
- 差分ビルド(`experimental.incrementalBuild`)は、ページが増えてビルドが遅くなってから入れます。

## 対象範囲

| 原文のサイト            | 原文のリポジトリ                                                  |
| ----------------------- | ----------------------------------------------------------------- |
| `code.visualstudio.com` | [microsoft/vscode-docs](https://github.com/microsoft/vscode-docs) |
| `docs.github.com`       | [github/docs](https://github.com/github/docs)                     |

この2つのサイトのうち、原文のリポジトリにMarkdownのあるページが対象です。原文のリポジトリに対応するファイルが無いページは、対応していない旨を表示し、原文へのリンクを出します。

## URL

このサイトは、持っているドメインのサブドメイン`ja.keke.works`で公開します。`keke.works`はCloudflareのDNSにあるので、WorkerのCustom Domainで証明書も自動で発行されます。このサイトのURLは、原文のURLを、このサイトのドメインの後ろにそのまま付けた形にします。

```text
原文:     https://code.visualstudio.com/docs/editor/codebasics
日本語訳: https://ja.keke.works/https://code.visualstudio.com/docs/editor/codebasics
```

- 読者は、原文のURLをコピーし、このサイトのドメインの後ろに貼るだけで日本語訳を開けます。
- `https://`を省いた形(`https://ja.keke.works/code.visualstudio.com/...`)も受け付けます。こちらを正規のURLとし、`https://`付きの形からはリダイレクトします。
- URLエンコードされた形(`https%3A%2F%2Fcode.visualstudio.com%2F...`)も受け付けます。Chromeのサイト内検索のショートカットから開くと、この形になるためです。
- GitHub Docsの`/en/`などの言語の部分は取り除きます。バージョンの部分(`/enterprise-cloud@latest/`など)は残し、そのバージョンの本文として訳します。

### 開き方の補助

サイトに、次の2つの設定方法を載せます。

- Chromeのサイト内検索のショートカット。URLを`https://ja.keke.works/%s`、ショートカットを`ja`にして登録します。読者は、アドレスバーに`ja`と入力してTabキーを押し、原文のURLを貼ってEnterキーを押せば、日本語訳を開けます。
- ブックマークレット。`javascript:location.href='https://ja.keke.works/'+location.href.replace(/^https?:\/\//,'')`をブックマークとして登録します。原文のページを開いた状態でこのブックマークを押せば、日本語訳を開けます。iPhoneのSafariでも使えます。

原文のホスト名の後ろにこのサイトのドメインを足す形(`code.visualstudio.com.ja.keke.works`)は採りません。アドレスバーでURLの途中を書き換える必要があり、貼り付けや入力の手間が増えるためです。

## ページの表示

### 日本語訳があるページ

ビルド時に静的なHTMLとして生成したページを表示します。

### 日本語訳が無いページ

Workerがその場でページを返します。

1. 原文のリポジトリに対応するファイルがあるかを確かめます。無ければ、対応していない旨と原文へのリンクを表示します。
2. ファイルがあれば、翻訳をリクエストするボタンと、原文へのリンクを表示します。翻訳済みでないことが一目で分かるようにします。
3. 読者がボタンを押すと、順番待ちの列に入ります。ページは処理の状況を定期的に確かめ、訳し終えたら日本語訳を表示します。

ページを開いただけでは翻訳を始めません。ボタンを押したときだけ始めます。検索エンジンなどのbotがページを巡回しただけで、無料枠を使い切るのを防ぐためです。ボタンには、Cloudflare Turnstileのbot判定を付けます。Turnstileの無料プランは、判定の回数に上限がありません。

### ページ内のリンク

訳文の中の、ほかのページへのリンクは、次のように書き換えます。

- リンク先に日本語訳があれば、このサイトの日本語訳へのリンクにします。
- リンク先に日本語訳が無ければ、原文のサイトへのリンクにします。

新しいページを訳すたびにサイト全体をビルドし直すので、リンクの書き換えも、その時点の日本語訳の有無に合わせて更新されます。

## 翻訳の進め方

リクエストされたページは、まず1日の上限が大きい無料モデルで訳して公開します。1日の上限が小さい無料モデルの訳は、リクエストの多いページから順に、あとから追加します。

翻訳は、順番待ちの列から自動で順に行います。

1. 読者が翻訳リクエストのボタンを押すと、WorkerがD1の順番待ちの列に記録します。同じページへのリクエストはまとめ、件数を数えます。
2. 記録と同時に、WorkerがGitHub Actionsのワークフローを毎回起動します。ActionsはwranglerでD1を直接読み書きします。Workerに列を操作するAPIを置かないので、共有の秘密が要りません。実行中かどうかはWorkerでは判定しません。同時に走らせないことは、Actionsの`concurrency`で保証します。実行中のジョブがあれば、新しいジョブはその終了を待ってから始まり、列を最初から確かめ直します。実行中のジョブが列の確認を終えた直後に入ったリクエストも、待っているジョブが拾います。
3. Actionsは、リクエストの多い順、同数なら古い順に、1回の実行で最大5ページを訳します。訳したら公開し、列に残っていれば次の実行を起動します。無料枠の1分あたりの上限を守ります。各ページはGemini 3.5 Flash-Liteで訳し、構造検査に落ちたら1回だけ訳し直します。それでも落ちたら、Gemini 3.8 Flashを推論の量`low`で使って訳します。Flash-Liteがその日の上限に達したら、残りの列はPLaMo 3 Translate 8BでActionsのCPUを使って訳し続けます。こちらは遅いので、読者の待ち時間は長くなります。Flash-Liteの訳は、上限が戻った後に追加します。
4. リクエストを契機にした起動とは別に、Actionsの`schedule`で1時間ごとにもワークフローを起動します。列が空なら、すぐに終わります。この起動が、上限が戻った後に、上限で後回しにしたFlash-Liteの訳と、追加の訳を進めます。
5. 訳し終えたら構造検査を通し、訳文をコミットします。列の状態は「公開待ち」にします。公開(ビルドとデプロイ)は別のワークフローで行い、済んだら「公開済み」にします。デプロイだけが失敗しても、訳し直さずにデプロイだけをやり直せます。
6. 未訳の断片が5%を超えたページは公開しません。APIの障害や無料枠の上限が原因なら列に戻し、それ以外は「失敗」にします。

翻訳モデルの1日の呼び出し回数は、D1に自分でも数え、無料枠の上限の手前(Flash-Lite 450回、3.8 Flash 18回)で止めます。Googleの上限の応答だけに頼ると、APIキーのプロジェクトに課金を設定したときに、上限を超えて有料で訳し続けてしまうためです。

受付には上限を置きます。同じIPからのリクエストは1分に5回まで、新しいページの受付は1日200件までです。原文のURLは、受け付ける前に正規化します。言語やバージョンの表記の揺れを1つにまとめ、使えない文字や`.`と`..`の区間を含むURL、Enterpriseの版のURLは受け付けません。

順番待ちの列は、Cloudflare QueuesではなくD1に置きます。Queuesの無料プランはメッセージの保持が24時間までで、翌日に持ち越したリクエストが消えるおそれがあるためです。

無料枠が廃止されたモデルは、その時点で翻訳の追加を止めます。作成済みの訳文は残します。

原文は公開文書なので、入出力が学習に使われる無料枠の利用を許容します。

## 訳文のモデルを切り替える

読者は、ページごとに、どのモデルの訳文を読むかを選べます。

- 訳文は、モデルごとに別のファイルで持ちます。
- 各ファイルに、モデルのID、設定値、翻訳元のコミット、翻訳日を記録します。
- 各ページに、既定のモデルを1つ決めます。
- 読者が切り替えた選択は、ブラウザに保存します。
- 切り替えはページ内で行い、モデルごとにURLを分けません。モデルごとにURLを分けると、検索結果に同じ内容のページが並びます。
- サイト内検索の対象は、既定の訳だけです。
- 構造検査に通らなかった訳は、選択肢に出しません。
- 各ページに「この訳が読みやすい」のボタンを置き、票の多いモデルをそのページの既定にします。

## モデルの候補

無料で使えるモデルは次の4つです。

| モデル                      | 無料で使える範囲                      | 学習利用 | 役割の案                                                         |
| --------------------------- | ------------------------------------- | -------- | ---------------------------------------------------------------- |
| Gemini 3.5 Flash-Lite無料枠 | 1日500リクエスト                      | あり     | リクエスト直後の翻訳                                             |
| Gemini 3.8 Flash無料枠      | 1日20リクエスト                       | あり     | リクエストの多いページへの追加の訳                               |
| PLaMo 3.1 Prime無料プラン   | 24時間で50回                          | あり     | リクエストの多いページへの追加の訳                               |
| PLaMo 3 Translate 8B        | GitHub ActionsでCPU実行すれば上限なし | なし     | Gemini 3.5 Flash-Liteの1日の上限に達したときの代わりと、追加の訳 |

- Geminiの無料枠の上限は、プロジェクトごとに違うという報告があります。実際の値は、APIキーを作ってから確かめます。
- PLaMo 3 Translate 8Bは、非商用であれば登録なしで無償利用できます。公開リポジトリのGitHub Actionsの標準ランナー(4 vCPU、メモリ16GB)で、4bit量子化のGGUFをCPUで動かします。APIの上限が無い代わりに、1ページに数分以上かかる見込みです。実際の速度は試訳で測ります。
- PLaMo 3.1 Primeの無料プランは、利用者の登録が必要です。24時間で50回という上限は、[PLaMo APIの料金プラン](https://plamo.preferredai.jp/api)の記載です。[制限事項](https://docs.plamo.preferredai.jp/ja/limit)のページには、無料プランのPrimeの上限が載っていません。実際の上限は、登録してから確かめます。

### 試訳の結果

2026-11-16に、Geminiの2つのモデルで試訳しました。結果は`trial`ブランチの`trial/out`と`trial/out2`にあります。

| 訳し方                                                  | 構造検査に合格                                       | 1ページの時間 |
| ------------------------------------------------------- | ---------------------------------------------------- | ------------- |
| Flash-Lite 1回                                          | 5ページ中3ページ                                     | 2〜13秒       |
| Flash-Lite、落ちたら訳し直し、それでも落ちたら3.8 Flash | 5ページすべて(訳し直しで2ページ、3.8 Flashで1ページ) | 13〜158秒     |
| 3.8 Flash推論の量は既定                                 | 5ページすべて                                        | 84〜296秒     |
| 3.8 Flash推論の量は`low`                                | 5ページすべて                                        | 36〜172秒     |

- どの訳も自然な日本語でした。
- Flash-Liteの不合格は、すべて退避した箇所の目印の取り違えです。目印を2回書いて別の目印を落とす、目印の中のLiquidの変数名を書き換える、などです。
- 3.8 Flashは、推論の量を`low`にすると推論のトークンが0になりました。訳の差は言い回し程度です。`low`でも遅いのは、出力の生成が遅いためです。
- 目印の形を変えて、Flash-Liteで5ページを3回ずつ訳しました(`trial/out4`、`trial/out5`)。1回で構造検査に通った数は、連番とヒントの形で15回中8回、ランダムなIDで12回、ランダムなIDに変数の展開を加えて13回でした。回数が少ないので、差は傾向として扱います。
- 骨組みをプログラムが持ち、断片をJSONで訳す形では、Flash-Liteで5ページを3回ずつ訳した15回すべてが構造検査に通りました(`trial/seg1`、`trial/seg2`)。変数を展開した形では、約1,000の断片で落ちたものは0、対応表を渡す形では6でした。落ちた6つも、断片だけの訳し直しで通りました。
- この結果から、Flash-Liteで訳し、訳し直しと3.8 Flashで補う形にしました。PLaMoの2つのモデルは、まだ試していません。

## 翻訳APIに送るもの

翻訳APIに送るのは、翻訳対象の原文と、どの文書にも共通の翻訳の指示だけです。個人の情報や、原文以外の情報は送りません。

## 品質の担保

- コードブロック、行内コード、リンク先のURL、Liquidタグ、HTMLコメントは、訳す前に目印に置き換えて退避し、訳した後に戻します。
- 目印は`⟦K7QM⟧`の形で、中身は意味のないランダムなIDにします。取り違えやすい文字(I、L、O、U、0、1)を除いた30文字から4文字を選び、どの2つのIDも2文字以上違うようにします。1文字の書き間違いなら、どの目印かが一意に決まるので自動で直します。連番や中身のヒントを入れると、モデルが隣の番号やヒントの中身を推測して書き換えるためです。
- Markdownの骨組みは、プログラムが持ちます。見出しやリストの記号、字下げ、表の区切り、コードブロックはモデルに渡しません。モデルには文の断片だけを、番号付きのJSONで渡し、同じ番号のJSONで受け取ります。返答の形は、APIの構造化出力で強制します。ページの断片は1回でまとめて渡すので、文脈は失いません。
- 断片ごとに検査し、落ちた断片だけを訳し直します。それでも落ちたら別のモデルで訳し、最後まで落ちた断片は原文のまま残します。構造はプログラムが組み立てるので、崩れたページは公開されません。
- `{% data variables.… %}`も目印にし、目印が何を表すかの対応表を、訳す断片の外で一緒に渡します。モデルは意味を分かったうえで訳し、目印の中身は変わりません。値に展開して見せる形も試しましたが、`Agents window`や`Copilot cloud agent`などの1割以上が訳されたり書き換えられたりしました。
- 変数には、製品名のほかに`public preview`や`custom agent`のような一般の語もあります。変数ごとに、英語のまま残すか、決まった訳語にするかを用語集に書き、目印を戻すときに用語集の値を入れます。どのページでも同じ表記になります。
- 行内コードとリンク先は、退避せずに見せる形も試しましたが、モデルがURLを書き換える(`agent-customization`を`agent-agent-customization`にする、など)ため、退避します。
- 日本語と英数字の間の空白は、指示しても多く入るので、訳した後に機械的に取り除きます。
- 訳した後に、見出し、リスト、表、コードブロックの構造が原文と一致するかを、プログラムで検査します。
- 同じ検査で、リンクと画像も確かめます。リンク先のURLと画像のパスが原文と一致すること、内部リンクのアンカーが訳文側に存在することを見ます。退避したリンクをモデルが落とすと、構造が一致していてもリンク切れになるためです。
- 見出しのアンカーIDは、訳文でも原文の見出しから作ったIDのまま残します。見出しを訳すとIDが変わり、原文のIDを指す内部リンクが切れるためです。訳文の見出しには、原文のIDを明示的に付けます。
- 強調の記号(`**`や`_`)が日本語に隣接すると、CommonMarkの規則では強調になりません。表示するときに、日本語の文字の前後でも強調と判定するように直します。
- リントは、この構造検査だけから始めます。文体や用語の規則は、実際の訳文で問題が出てから足します。
- 文体と用語は、[訳し方の指針と用語集](translation-guidelines.md)の決定事項に従います。

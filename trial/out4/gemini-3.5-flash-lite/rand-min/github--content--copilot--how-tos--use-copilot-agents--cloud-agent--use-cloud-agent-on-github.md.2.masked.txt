## Introduction

⟦8ZCQ⟧ セッションは、⟦ZJ6Q⟧ 内のいくつかの場所から開始できます。セッションが実行されたら、ブラウザを離れることなく、その進捗状況を監視したり、フォローアップのプロンプトで指示を与えたり、結果として得られた pull request を反復的に改善したりできます。

⟦EZZR⟧ の詳細については、[AUTOTITLE](/copilot/concepts/copilot-surfaces/copilot-on-github) を参照してください。

また、⟦WQCF⟧ を使用して、これらと同じエントリポイントからパートナーが構築したエージェントを開始することもできます。詳細については、[AUTOTITLE](/copilot/how-tos/use-copilot-agents/cloud-agent/use-agent-apps) を参照してください。

## Starting a ⟦RD4J⟧ session

いくつかの異なるエントリポイントからセッションを開始できます。

* [github.com/copilot](https://github.com/copilot?ref_product=copilot&ref_type=engagement&ref_style=text&utm_source=cloud-gh-docs-home-cta&utm_medium=docs&utm_campaign=universe-2026) にある ⟦V46C⟧ ⟦NFP4⟧ のホーム ページ。
* [https://github.com](https://github.com?ref_product=copilot&ref_type=engagement&ref_style=text) にサインインした状態での、⟦MSF9⟧ ⟦89WG⟧ のパーソナル ダッシュボードまたは ⟦KRTD⟧ のホーム ページ。
* リポジトリ内の **⟦8GCX⟧ Agents** タブまたはパネル。

デフォルト設定ですぐにプロンプトを送信することも、プロンプトを送信する前にタスクに合わせてセッションを構成することもできます。

1. プロンプトボックスに、⟦4CJN⟧ に実行させたい内容を入力します。求められる結果と制約事項を含めます。

   > [!TIP]
   > プロンプトでスラッシュコマンドを使用して特定のアクションを実行することもできます。たとえば、第2の意見を得るための `/rubber-duck`、リポジトリの脆弱性をレビューするための `/security-review`、セッションの使用状況情報を表示するための `/usage` などがあります。

1. オプションで、**⟦6R44⟧ Attach** をクリックして、⟦HTB9⟧ にリクエストのための参照情報を提供します。

   リクエストのコンテキストを提供するには、**Files and folders**、**Upload from computer**、**Repository**、または **Space** を選択します。

   クラウドサンドボックスセッションの場合、コネクタや個人のカスタム MCP サーバーを設定することで、サードパーティのソースから追加のコンテキストを提供できます。[AUTOTITLE](/copilot/concepts/customizations/copilot-connectors) および [AUTOTITLE](/copilot/concepts/customizations/mcp#personal-mcp-servers) を参照してください。

1. **Mode** ピッカーを開いて、⟦VW66⟧ とどのように共同作業を行うかを選択します。

   * **Interactive**: (デフォルト) ⟦ATFC⟧ と段階的に作業を進めます。
   * **Autopilot**: ⟦35TG⟧ にタスクを委任して、最初から最後まで実行させます。

   同じメニューで、**Tool permissions** を使用してツールリクエストの承認方法を制御します。

   * **Assisted** (デフォルト) を選択します。これは、安全チェックを使用してリクエストを承認するかどうか、またはユーザーに確認するかを決定します。
   * リクエストごとに承認を必須にするには、**Always ask** を選択します。
   * すべてのツール、パス、および URL リクエストを自動的に承認するには、**Allow all** を選択します。

1. **Models** ピッカーを開き、**Auto** (デフォルト) または特定のモデルを選択します。モデルは、速度とコスト効率、汎用性と知能、または複雑なタスクに対する能力のどれを優先して選択するかを判断しやすくするために、その長所ごとにグループ化されています。選択したモデルが **Balance** などの設定可能な推論をサポートしている場合は、ドロップダウンメニューを使用して推論レベルを選択することもできます。

1. プロンプトボックスの下部にある **Chat** セッションコンテキストピッカーを使用して、セッションのスコープ (個人、組織、またはリポジトリ) を選択します。

   * 検索ボックスにリポジトリ名を入力して、追加するリポジトリを検索します。
   * **Ask anything across repositories** の下にある **Chat** を選択して、複数のリポジトリにわたって質問します。デフォルトのスコープは個人のリポジトリです。右側の画像をクリックしてアカウントメニューを開き、組織を選択するか、リポジトリの所有者 (ユーザーまたは組織) で検索してスコープを変更します。
   * **Work in a repository** の下で、作業を行う最近のリポジトリを選択します。リストされるリポジトリには、選択したスコープが反映されます。

   > [!NOTE]
   > * **Attach** メニュー (前の手順) からリポジトリを追加すると、プロンプトの参照 (コンテキスト資料) が提供されます。一方、ここ **Start a session** でリポジトリを選択すると、そのリポジトリがセッションの作業用リポジトリ (スコープ) になります。セッションの開始時に、クラウドサンドボックスはリポジトリのコピーを作成し、既存の制約内でそのコンテンツを操作する権限を ⟦MPJA⟧ に付与します。
   > * リポジトリがリストに表示されない場合は、個人設定、組織、またはエンタープライズポリシーによって ⟦8Z7P⟧ から除外されている可能性があります。

   オプションで、上記でリポジトリを選択した場合、**main** (またはリストされているデフォルトブランチ名) をクリックして、⟦QS2Y⟧ が作業コンテキストとして使用し、その中で操作を行うブランチを選択することもできます。

⟦G2DP⟧

1. **Send message** をクリックするか、<kbd>Enter</kbd> キーを押してプロンプトを送信し、セッションを開始します。

⟦RYT9⟧ はプロンプトに応答し、選択したコンテキストと環境に基づいてセッションを開始します。要求された場合、⟦HRDP⟧ は変更されたファイルのリスト、pull request、生成した成果物 (調査計画など)、およびその他の関連する出力を生成します。

### Starting ⟦DEBK⟧ from within a file, issue, or pull request

コンテキストページから ⟦9P8S⟧ とのチャットセッションを開くと、セッションは開いているファイル、issue、または pull request のコンテキストから始まります。

コンテキストパネル内から新しいエージェントセッションを開始することはできません。⟦A9AJ⟧ ページ、ホーム ページ、またはエージェントタブから開始する必要があります。

## Continuing work on a pull request

既存の pull request の変更やレビューコメントへの対応を ⟦M9KF⟧ に依頼できます。その後、結果のセッションを追跡し、フォローアップの指示を提供できます。

### Asking ⟦VCRF⟧ to make changes

pull request のコメントで `@copilot` をメンションして、⟦PM6F⟧ に変更を依頼できます。これは、⟦5VMA⟧ によって作成された pull request や、あなたや他の人が作成した pull request で機能します。

デフォルトでは、⟦MKWY⟧ は pull request ブランチに直接コミットをプッシュします。代わりに個別の pull request を作成するには、コメントでその旨を説明してください。自分でブランチをチェックアウトして変更をプッシュすることもできます。

⟦GVAP⟧ Web インターフェイスから pull request コメント (レビューやレビューコメントではない) を送信する場合は、モデルピッカーでモデルを選択します。⟦XVHX⟧ はデフォルトで元の pull request のモデルを使用します。

### Delegating review comments

レビューコメントを委任して、人間のレビュアーや ⟦GYCV⟧ からのフィードバックを ⟦4AMM⟧ に実装させることができます。

1. pull request で、**Files changed** タブを開きます。
2. ⟦TQM6⟧ に実装させたい最初のレビューコメントに移動します。
   * 1つのコメントを委任するには、**Fix with ⟦4TFE⟧** をクリックします。
   * 複数のコメントを委任するには、**Add to batch** をクリックします。作業させたいコメントの追加を続けます。
3. **Manage batch** パネルで、追加の指示を追加し、必要に応じてモデルピッカーでモデルを選択します。
4. ⟦HZJC⟧ に変更を適用する方法を選択します。
   * 変更をブランチに直接コミットするには、**⟦6TZR⟧ Fix and commit** をクリックします。
   * 変更を加えた新しい pull request を ⟦X6ZG⟧ に作成させるには、ドロップダウンメニューから **Fix and open pull request** をクリックします。

## Resolving merge conflicts

pull request のマージコンフリクトを解決するように ⟦NQQW⟧ に依頼するには、2つの方法があります。

* **「Fix with ⟦YTX3⟧」ボタンの使用**: pull request にマージコンフリクトがある場合は、マージボックスに表示される **Fix with ⟦3P2J⟧** ボタンをクリックします。
* **@copilot メンションの使用**: pull request のコメントで `@copilot` をメンションし、コンフリクトの修正を依頼します (例: "@copilot resolve the merge conflicts on this PR.")。

⟦Q57K⟧ は、コンフリクトしている変更を分析して解決し、ビルド、テスト、リンターが引き続き合格することを確認します。その後、マージする前に解決を確認できるようにレビューを要求します。

## はじめに

<x id="ZJ6Q"/> のさまざまな場所から <x id="8ZCQ"/> セッションを開始できます。セッションの実行中は、ブラウザを離れることなく、その進捗を監視したり、追加プロンプトで誘導したり、結果の pull request を反復して改善したりできます。

<x id="EZZR"/> の詳細については、[AUTOTITLE](<x id="TEPX"/>) を参照してください。

また、<x id="WQCF"/> を使用して、これらの同じエントリポイントからパートナーが構築したエージェントを開始することもできます。詳細については、[AUTOTITLE](<x id="4H2R"/>) を参照してください。

## <x id="RD4J"/> セッションの開始

いくつかの異なるエントリポイントからセッションを開始できます。

* [github.com/copilot](<x id="RADB"/>) にある <x id="V46C"/> の <x id="NFP4"/> ホームページ
* [https://github.com](<x id="FW4F"/>) にサインインした状態の <x id="MSF9"/> の <x id="89WG"/> パーソナルダッシュボードまたは <x id="KRTD"/> ホームページ
* リポジトリ内の **<x id="8GCX"/> Agents** タブまたはパネル

デフォルト設定のままプロンプトをすぐに送信することも、プロンプトを送信する前にタスクに合わせてセッションを設定することもできます。

1. プロンプトボックスに、<x id="4CJN"/> に実行させたい内容を入力します。希望する結果と制約事項を含めてください。

   > [!TIP]
   > プロンプト内でスラッシュコマンドを使用して、2番目の意見を求めるための <x id="6AQ6"/>、リポジトリの脆弱性をレビューするための <x id="KJDE"/>、セッションの使用状況情報を表示するための <x id="MWBT"/> など、特定のアクションを実行することもできます。

1. オプションで、**<x id="6R44"/> Attach** をクリックして、<x id="HTB9"/> にリクエストの参照情報を提供します。

   リクエストのコンテキストを提供するために、**Files and folders**、**Upload from computer**、**Repository**、または **Space** を選択します。

   クラウドサンドボックスセッションの場合、コネクタや個人のカスタム MCP サーバーを設定することで、サードパーティソースから追加のコンテキストを提供できます。[AUTOTITLE](<x id="PJ9K"/>) および [AUTOTITLE](<x id="VETP"/>) を参照してください。

1. **Mode** ピッカーを開いて、<x id="VW66"/> とどのように連携するかを選択します。

   * **Interactive**: (デフォルト) <x id="ATFC"/> とステップバイステップで作業します。
   * **Autopilot**: エンドツーエンドの実行を <x id="35TG"/> に委任します。

   同じメニューで、**Tool permissions** を使用してツールリクエストの承認方法を制御します。

   * **Assisted** (デフォルト) を選択すると、安全性チェックを使用してリクエストを承認するかユーザーに確認するかを決定します。
   * **Always ask** を選択すると、リクエストごとに承認が必要になります。
   * **Allow all** を選択すると、すべてのツール、パス、および URL リクエストが自動的に承認されます。

1. **Models** ピッカーを開き、**Auto** (デフォルト) または特定のモデルを選択します。モデルは、速度とコスト効率、汎用性と知能、または複雑なタスクの処理能力のいずれかを選択できるように、長所ごとにグループ化されています。選択したモデルが **Balance** などの設定可能な推論をサポートしている場合は、ドロップダウンメニューを使用して推論レベルを選択することもできます。

1. プロンプトボックスの下部にある **Chat** セッションコンテキストピッカーを使用して、セッションのスコープ (個人、組織、またはリポジトリ) を選択します。

   * 検索ボックスに追加するリポジトリ名を入力してリポジトリを検索します。
   * **Ask anything across repositories** の下で **Chat** を選択すると、複数のリポジトリにまたがって質問できます。デフォルトのスコープは個人のリポジトリです。右側の画像をクリックしてアカウントメニューを開き、組織を選択するか、リポジトリ所有者 (ユーザーまたは組織) で検索してスコープを変更します。
   * **Work in a repository** の下で、作業を行う最近のリポジトリを選択します。リストされるリポジトリは、選択したスコープを反映しています。

   > [!NOTE]
   > * **Attach** メニュー (前のステップ) を介してリポジトリを追加すると、プロンプトの参照 (コンテキスト資料) が提供されます。一方、ここ **Start a session** の下で選択すると、そのリポジトリがセッションの作業リポジトリ (スコープ) になります。セッションの開始時に、クラウドサンドボックスはそのリポジトリのコピーを作成し、既存の制約内でそのコンテンツを操作する権限を <x id="MPJA"/> に付与します。
   > * リポジトリがリストに表示されない場合、個人の設定、または組織やエンタープライズのポリシーによって <x id="8Z7P"/> から除外されている可能性があります。

   オプションで、上記でリポジトリを選択している場合、**main** (またはリストされているデフォルトブランチ名) をクリックして、<x id="QS2Y"/> が作業コンテキストとして使用し、その中で操作するブランチを選択することもできます。

<x id="G2DP"/>

1. **Send message** をクリックするか、<kbd>Enter</kbd> キーを押してプロンプトを送信し、セッションを開始します。

<x id="RYT9"/> は選択されたコンテキストと環境に基づいてプロンプトに応答し、セッションを開始します。要求された場合、<x id="HRDP"/> は変更されたファイルのリスト、pull request、生成された成果物 (リサーチプランなど)、およびその他の関連する出力を生成します。

### ファイル、issue、または pull request 内からの <x id="DEBK"/> の開始

コンテキストページから <x id="9P8S"/> とのチャットセッションを開くと、セッションはオープンなファイル、issue、または pull request のコンテキストから始まります。

コンテキストパネル内から直接新しいエージェントセッションを開始することはできません。<x id="A9AJ"/> ページ、ホームページ、またはエージェントタブから開始する必要があります。

## pull request での作業の継続

既存の pull request の変更やレビューコメントへの対応を <x id="M9KF"/> に依頼できます。その後、結果のセッションを追跡し、追加の指示を提供できます。

### 変更を <x id="VCRF"/> に依頼する

任意の pull request のコメント内で <x id="HP63]]」をメンションして、変更を加えるように <x id="PM6F"/> に依頼できます。これは、<x id="5VMA"/> によって作成された pull request や、あなたや他の人が作成した pull request で機能します。

デフォルトでは、<x id="MKWY"/> は pull request ブランチに直接コミットをプッシュします。代わりに別の pull request を作成するには、その旨をコメントに記述します。ブランチをチェックアウトして自分で変更をプッシュすることもできます。

<x id="GVAP"/> Web インターフェースから pull request コメント (レビューやレビューコメントではない) を送信する場合は、モデルピッカーでモデルを選択します。<x id="XVHX"/> はデフォルトで元の pull request のモデルを使用します。

### レビューコメントの委任

人間のレビュアーや <x id="GYCV"/> からのフィードバックを <x id="4AMM"/> に実装させるようにレビューコメントを委任できます。

1. pull request で **Files changed** タブを開きます。
1. <x id="TQM6"/> に実装させたい最初のレビューコメントに移動します。
   * 1つのコメントを委任するには、**Fix with <x id="4TFE"/>** をクリックします。
   * 複数のコメントを委任するには、**Add to batch** をクリックします。作業させたいコメントの追加を続けます。
1. **Manage batch** パネルで追加の指示を追加し、必要に応じてモデルピッカーでモデルを選択します。
1. <x id="HZJC"/> に変更を適用する方法を選択します。
   * 変更をブランチに直接コミットするには、**<x id="6TZR"/> Fix and commit** をクリックします。
   * 変更を加えた新しい pull request を <x id="X6ZG"/> に作成させるには、ドロップダウンメニューから **Fix and open pull request** をクリックします。

## マージコンフリクトの解決

pull request のマージコンフリクトを解決するように <x id="NQQW"/> に依頼するには、2つの方法があります。

* **「Fix with <x id="YTX3"/>」ボタンの使用**: pull request にマージコンフリクトがある場合は、マージボックスに表示される **Fix with <x id="3P2J"/>** ボタンをクリックします。
* **@copilot メンションの使用**: pull request のコメント内で <x id="VXNF"/> をメンションし、コンフリクトを修正するように依頼します (例: "@copilot resolve the merge conflicts on this PR")。

<x id="Q57K"/> は競合する変更を分析して解決し、ビルド、テスト、およびリンターが引き続き合格することを確認します。その後、マージ前に解決を確認できるようにレビューを依頼します。

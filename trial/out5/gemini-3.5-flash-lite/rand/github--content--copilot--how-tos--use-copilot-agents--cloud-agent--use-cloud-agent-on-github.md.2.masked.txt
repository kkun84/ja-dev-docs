## はじめに

GitHub上のさまざまな場所から、クラウドでの GitHub Copilot セッションを開始できます。セッションが実行されたら、その進行状況を監視したり、後続のプロンプトで指示を与えたり、ブラウザを離れることなく結果の pull request で反復作業を行ったりできます。

クラウドでの Copilot の詳細については、[AUTOTITLE](⟦FBRD⟧) を参照してください。

また、エージェントアプリを使用して、これらと同じエントリーポイントからパートナー製のエージェントを開始することもできます。詳細については、[AUTOTITLE](⟦CHDN⟧) を参照してください。

## クラウドでの Copilot セッションの開始

さまざまなエントリーポイントからセッションを開始できます。

* ⟦github.com/copilot⟧(⟦PJVJ⟧) にある Copilot ⟦8ZCQ⟧ のホームページ。
* サインインした状態で ⟦https://github.com⟧(⟦TT3R⟧) にアクセスしたときの、⟦ZJ6Q⟧ の GitHub パーソナルダッシュボードまたは ⟦EZZR⟧ のホームページ。
* リポジトリ内の **⟦WQCF⟧ Agents** タブまたはパネル。

デフォルト設定のまますぐにプロンプトを送信することも、プロンプトを送信する前にタスクに合わせてセッションを設定することもできます。

1. プロンプトボックスに、Copilot に実行させたい内容を入力します。希望する結果と制約事項を含めてください。

   > [!TIP]
   > プロンプト内でスラッシュコマンドを使用して、2番目の意見を求める ⟦A9AJ⟧、脆弱性がないかリポジトリをレビューする ⟦MZH6⟧、セッションの使用状況情報を表示する ⟦EVN8⟧ などの特定のアクションを実行することもできます。

1. 必要に応じて、**⟦RD4J⟧ Attach** をクリックして、Copilot にリクエストの参照情報を提供します。

   **Files and folders**、**Upload from computer**、**Repository**、または **Space** を選択して、リクエストのコンテキストを提供します。

   クラウドサンドボックスセッションの場合、コネクタや個人のカスタム MCP サーバーを設定することで、サードパーティソースからの追加コンテキストを提供できます。[AUTOTITLE](⟦DAAB⟧) と [AUTOTITLE](⟦6ETX⟧) を参照してください。

1. **Mode** ピッカーを開いて、Copilot とどのように連携するかを選択します。

   * **Interactive**: (デフォルト) Copilot とステップバイステップで作業します。
   * **Autopilot**: タスクを Copilot に委任して、エンドツーエンドで実行させます。

   同じメニューで、**Tool permissions** を使用してツールリクエストの承認方法を制御します。

   * **Assisted** (デフォルト) を選択します。安全性チェックを使用して、リクエストを承認するか尋ねるかを決定します。
   * **Always ask** を選択して、リクエストごとに承認を必須にします。
   * **Allow all** を選択して、すべてのツール、パス、および URL リクエストを自動的に承認します。

1. **Models** ピッカーを開き、**Auto** (デフォルト) または特定のモデルを選択します。モデルは、速度とコスト効率、汎用性と知性、または複雑なタスクの能力のどれを重視するかを選びやすいように、その長所ごとにグループ化されています。選択したモデルが **Balance** などの設定可能な推論をサポートしている場合は、ドロップダウンメニューを使用して推論レベルを選択することもできます。

1. プロンプトボックスの下にある **Chat** セッションコンテキストピッカーを使用して、セッションのスコープ (個人、組織、またはリポジトリ) を選択します。

   * 検索ボックスにリポジトリ名を入力して、追加するリポジトリを検索します。
   * **Ask anything across repositories** の下にある **Chat** を選択して、複数のリポジトリにわたって質問します。デフォルトのスコープは個人のリポジトリです。右側の画像をクリックしてアカウントメニューを開き、組織を選択するか、リポジトリの所有者 (ユーザーまたは組織) で検索してスコープを変更します。
   * **Work in a repository** の下で、作業する最近のリポジトリを選択します。リストされるリポジトリは、選択したスコープを反映します。

   > [!NOTE]
   > * **Attach** メニュー (前のステップ) を通じてリポジトリを追加すると、プロンプトの参照 (コンテキスト資料) が提供されます。一方、ここで **Start a session** の下で選択すると、そのリポジトリがセッションの作業リポジトリ (スコープ) になります。セッションの開始時に、クラウドサンドボックスがリポジトリのコピーを作成し、既存の制約内でそのコンテンツを操作する権限を Copilot に付与します。
   > * リポジトリがリストに表示されない場合、個人設定、あるいは組織やエンタープライズのポリシーによって Copilot から除外されている可能性があります。

   オプションで、上記のリポジトリを選択している場合は、**main** (またはリストされているデフォルトブランチ名) をクリックして、Copilot が作業コンテキストとして使用し、その中で操作を行うブランチを選択することもできます。

⟦V46C⟧

1. **Send message** をクリックするか、<kbd>Enter</kbd> キーを押してプロンプトを送信し、セッションを開始します。

Copilot はプロンプトに応答し、選択したコンテキストと環境に基づいてセッションを開始します。要求された場合、Copilot は変更されたファイルのリスト、pull request、生成された成果物 (リサーチプランなど)、およびその他の関連する出力を生成します。

### ファイル、issue、または pull request 内からの Copilot の開始

コンテキストページから Copilot とのチャットセッションを開くと、開いているファイル、issue、または pull request のコンテキストからセッションが始まります。

コンテキストパネル内から新しいエージェントセッションを開始することはできません。Copilot ページ、ホームページ、またはエージェントタブから開始する必要があります。

## Copilot への issue の割り当て

Copilot に issue を割り当てることで、issue の作業を開始するように依頼できます。Copilot はタスクの作業を開始し、pull request を作成し、完了するとあなたにレビューを要求します。

> [!NOTE]
> この機能はパブリックプレビュー段階であり、変更される可能性があります。

⟦HTB9⟧
⟦VW66⟧

1. Copilot に割り当てたい issue を開きます。
1. 右側のメニューで **Assignees** をクリックします。

   ![issue の右サイドバーのスクリーンショット。「Assignees」というラベルの付いたヘッダーが濃いオレンジ色で囲まれています。](⟦DH7A⟧)

1. 割り当て先リストから **Copilot** をクリックします。

   ![issue上の「Assignees」ウィンドウのスクリーンショット。リストで Copilot が利用可能です。](⟦ZP8Z⟧)

   追加のオプションが表示されます。

   ![ターゲットリポジトリ、開始ブランチ、カスタムエージェント、および追加の指示のオプションを表示する「Assign to Copilot」ダイアログのスクリーンショット。](⟦SVGW⟧)

1. **Optional prompt** フィールドに、Copilot に対する具体的なガイダンスを追加できます。Copilot がタスクを理解して完了するのに役立つコンテキスト、制約、または特定の要件を追加します。

   たとえば、使用する特定のコーディングパターンやフレームワーク、テスト要件、コードスタイルの好み、変更すべき、または変更すべきではないファイルやディレクトリに関する指示を含めることができます。

   ここで提供する詳細に加えて、Copilot はターゲットリポジトリ用に設定されたカスタム指示を使用します。[AUTOTITLE](⟦RBQR⟧) を参照してください。

1. ダイアログのドロップダウンメニューを使用して、Copilot が作業するリポジトリと、分岐元のブランチを変更できます。

   **少なくとも**読み取りアクセス権を持つすべてのリポジトリが、リポジトリのドロップダウンメニューに表示されます。ただし、書き込みアクセス権があり、**かつ**そのリポジトリで Copilot クラウドエージェントが有効になっている場合にのみ、リポジトリを選択できます。

   issue のソース組織とは異なる組織のリポジトリを選択した場合、または issue がプライベートリポジトリにあるときにパブリックリポジトリを選択した場合、警告が表示されます。

   リポジトリを指定しない場合、Copilot は issue と同じリポジトリで作業します。ブランチを指定しない場合、Copilot は選択したリポジトリのデフォルトブランチから作業します。

   > [!TIP]
   > Copilot に issue を割り当てると、issue のタイトル、説明、既存のコメント、および提供した追加の指示が送信されます。issue を割り当てた後、Copilot は issue に追加されたそれ以降のコメントを認識しないため、反応しません。追加の情報や、元の要件に対する変更がある場合は、Copilot が作成する pull request のコメントとして追加してください。

## 失敗した GitHub Actions ワークフロー実行の修正

pull request ブランチで GitHub Actions ワークフローの実行が失敗した場合は、Copilot に調査と失敗の修正を依頼できます。

1. GitHub で、失敗したワークフローの実行ジョブページに移動します。
1. **⟦RYT9⟧ Fix with Copilot** ボタンをクリックします。

   Copilot が新しいセッションを開始し、失敗の原因を調査し、ブランチに修正をプッシュします。

## pull request での作業の継続

Copilot に変更を加えるよう依頼したり、既存の pull request のレビューコメントに対処させたりすることができます。その後、結果のセッションを追跡し、後続の指示を提供できます。

### Copilot に変更の作成を依頼する

任意の pull request のコメントで ⟦S6VM⟧ をメンションして、Copilot に変更を加えるよう依頼できます。これは、Copilot が作成した pull request や、あなたや他のユーザーが作成した pull request で機能します。

デフォルトでは、Copilot はコミットを pull request ブランチに直接プッシュします。代わりに別の pull request を作成するには、コメントでその旨を説明してください。自分でブランチをチェックアウトして変更をプッシュすることもできます。

GitHub Web インターフェースから pull request コメント (レビューやレビューコメントではない) を送信する場合は、モデルピッカーでモデルを選択します。Copilot はデフォルトで元の pull request のモデルを使用します。

### レビューコメントの委任

レビューコメントを委任して、人間のレビュアーや GitHub Copilot code review からのフィードバックを Copilot に実装させることができます。

1. pull request で **Files changed** タブを開きます。
1. Copilot に実装させたい最初のレビューコメントに移動します。
   * 1つのコメントを委任するには、**Fix with Copilot** をクリックします。
   * 複数のコメントを委任するには、**Add to batch** をクリックします。Copilot に作業させたいコメントを追加し続けます。
1. **Manage batch** パネルで、追加の指示を追加し、必要に応じてモデルピッカーでモデルを選択します。
1. Copilot に変更を適用する方法を選択します。
   * 変更をブランチに直接コミットするには、**⟦HRDP⟧ Fix and commit** をクリックします。
   * Copilot に変更を加えた新しい pull request を作成させるには、ドロップダウンメニューから **Fix and open pull request** をクリックします。

### セッションの追跡と継続

⟦DEBK⟧

コメントに応答して Copilot が新しいセッションを開始すると、コメントに目の絵文字 (👀) のリアクションが表示されます。「Copilot has started work」イベントが pull request のタイムラインに表示されます。

![目のリアクションが付いたレビューコメントと「Copilot started work」タイムラインイベントが表示されている pull request タイムラインのスクリーンショット。](⟦JNDQ⟧)

Copilot は同じ pull request での以前のセッションのコンテキストを記憶しているため、後続のリクエストはより高速かつ確実になります。pull request がカスタムエージェントによって作成された場合は、⟦MSSF⟧ をメンションすることで、その同じエージェントの使用が継続されます。

## マージコンフリクトの解決

pull request のマージコンフリクトを解決するように Copilot に依頼するには、2つの方法があります。

* **「Fix with Copilot」ボタンの使用**: pull request にマージコンフリクトがある場合は、マージボックスに表示される **Fix with Copilot** ボタンをクリックします。
* **@copilot メンションの使用**: pull request のコメントで ⟦KZVC⟧ をメンションし、「@copilot resolve the merge conflicts on this PR」のようにコンフリクトを解決するように依頼します。

Copilot は競合する変更を分析し、それらを解決し、ビルド、テスト、およびリンターが引き続き合格することを確認します。その後、マージする前に解決を確認できるようにレビューを要求します。

## 自動化による Copilot の自動実行

スケジュールに従って、または issue がオープンされるなどのイベントに応答して、Copilot を自動的に実行する自動化を設定できます。自動化は、リポジトリの **Agents** タブにある **Automations** ペインから作成および管理できます。詳細については、[AUTOTITLE](⟦K7D2⟧) を参照してください。

## Copilot の作業に対するフィードバックの提供

Copilot の pull request やコメントにあるフィードバックボタンを使用して、出力を評価します。フィードバックは Copilot の品質向上に役立ちます。

1. Copilot の pull request またはコメントで、サムズアップ (:+1:) またはサムズダウン (:-1:) ボタンをクリックします。
1. サムズダウンボタンをクリックした場合は、必要に応じて理由を選択してコメントを残し、**Submit feedback** をクリックします。

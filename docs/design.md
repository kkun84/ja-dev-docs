# 設計

2026-11-16に作り直した設計です。この文書が、このリポジトリの設計の正本です。2026-11-11に書いた他の設計メモは、この文書と食い違う箇所ではこの文書を優先します。

金額は、2026-11-16に確認した料金と、2026-11-11の設計メモにあるトークン数の実測にもとづく見積もりです。

## 目的

VS CodeとGitHubの公式ドキュメントを、日本語で読めるサイトとして公開します。

- VS Codeのドキュメントには、公式の日本語版がありません。
- GitHub Docsには公式の日本語版がありますが、表や太字などの書式が崩れたページと、未訳のページがあります。

## 読者

自分と身近な人が読むことを前提にします。サイトは誰でも読める形で公開します。

## 予算

- 最初に使う費用は500円までです。
- その後の費用は、月ごとの上限額を決めて、その範囲に収めます。上限額は未決です。

## 対象範囲

| 対象 | 原文 | 訳す範囲 |
| --- | --- | --- |
| VS Code | [microsoft/vscode-docs](https://github.com/microsoft/vscode-docs) | 全ページ |
| GitHub Docs | [github/docs](https://github.com/github/docs) | 公式日本語版が崩れているページと、未訳のページ |

GitHub Docsの全ページは訳しません。公式日本語版と大半が重複するためです。

## 提供の形

- 対象の全ページのURLを、最初から用意します。URLは原文の構成に合わせます。
- 未翻訳のページには、英語の原文と、翻訳をリクエストするボタンを表示します。
- 1ページにつきURLは1つです。

## 翻訳の進め方

翻訳は2層に分けます。

1. 無料で使えるモデルで、対象の全ページを訳します。
2. 有料の高品質モデルの訳を、要望の多いページにだけ追加します。

有料モデルの翻訳は、夜間にまとめて行います。リクエストとアクセスの多い順に処理し、月の上限額を超えた分は翌月に回します。アクセスの瞬間には訳しません。botの巡回で費用が膨らむのを防ぐためです。

最初の500円は、エージェント関連の約20ページを高品質モデルで訳す費用と、要望分の費用に充てます。高品質モデルの費用は、1ページあたり約6円の見積もりです。

原文は公開文書なので、入出力が学習に使われる無料枠の利用を許容します。

## 訳文のモデルを切り替える

読者は、ページごとに、どのモデルの訳文を読むかを選べます。

- 訳文は、モデルごとに別のファイルで持ちます。
- 各ファイルに、モデルのID、設定値、翻訳元のコミット、翻訳日を記録します。
- 同じモデルの無料枠と有料枠は、訳文としては1つに扱います。両者の違いは料金と学習利用だけです。
- 各ページに、既定のモデルを1つ決めます。
- 読者が切り替えた選択は、ブラウザに保存します。
- 切り替えはページ内で行い、モデルごとにURLを分けません。モデルごとにURLを分けると、検索結果に同じ内容のページが並びます。
- サイト内検索の対象は、既定の訳だけです。
- 構造検査に通らなかった訳は、選択肢に出しません。
- 各ページに「この訳が読みやすい」のボタンを置き、票の多いモデルをそのページの既定にします。

Geminiの無料枠の上限は、プロジェクトごとに違うという報告があります。実際の値は、APIキーを作ってから確かめます。

候補から外したモデルは次のとおりです。

- PLaMo 3 Translateの0.8Bと2B。個人の比較で、文脈に依存する箇所の意味を保てた割合が低いと報告されています。
- GPT-6 LunaとClaude Haiku 5.5。日本語翻訳の評価が見つかっていません。
- Claude Opus 5.5とGPT-6 Astra。500円では数ページしか訳せません。

現行世代のモデルで、Markdown付きの技術文書を英日翻訳した中立の比較は見つかっていません。そのため、同じ5ページを次の4つで訳して比べます。

- Gemini 3.8 Flash 無料枠
- Gemini 3.5 Flash-Lite 無料枠
- PLaMo 3 Translate 8B
- Claude Sonnet 5.5

Claude Sonnet 5.5は、有料モデルの基準として入れます。

## 品質の担保

- コードブロック、リンク、Liquidタグは、訳す前に退避し、訳した後に戻します。
- 訳した後に、見出し、リスト、表、コードブロックの構造が原文と一致するかを、プログラムで検査します。
- リントは、この構造検査だけから始めます。文体や用語の規則は、実際の訳文で問題が出てから足します。
- 文体と用語は、[訳し方の指針と用語集](translation-guidelines.md)の決定事項に従います。

## 原文への追従

- 原文のリポジトリの差分を定期的に取り込みます。
- 訳済みのページは、変更があった部分だけを再翻訳します。
- 再翻訳が済むまでは、訳が古い旨をページに表示します。
- 未翻訳のページは、表示する英語の原文を更新します。

## ライセンスと帰属表示

- GitHub DocsのドキュメントはCC BY 4.0です。
- VS CodeのドキュメントはCC BY 3.0 USです。Microsoftの商標とロゴを使う権利は含まれません。

各ページの末尾に、次の内容を表示します。

- 原文の題名とURL
- 原著者
- ライセンスの名前とリンク
- 原文を日本語に翻訳したこと
- 表示中の訳文を作ったモデルの名前
- GitHubおよびMicrosoftとは関係のない非公式の翻訳であること

ロゴは使いません。帰属表示のひな形は[サイト構成案](site-structure.md)にあります。

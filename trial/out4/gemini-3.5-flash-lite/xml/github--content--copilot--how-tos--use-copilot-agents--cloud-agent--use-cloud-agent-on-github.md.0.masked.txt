## はじめに

<x id="VB25"/>上のさまざまな場所から <x id="SK43"/> セッションを開始できます。セッションの実行中は、ブラウザを離れることなく、その進捗を監視したり、フォローアップのプロンプトで誘導したり、結果として作成された pull request を反復的に改善したりできます。

<x id="PPTR"/>の詳細については、[AUTOTITLE](<x id="M4FJ"/>)を参照してください。

また、同じエントリーポイントから <x id="7TCN"/> を使用して、パートナーが構築したエージェントを開始することもできます。詳細については、[AUTOTITLE](<x id="9K7X"/>)を参照してください。

## <x id="TVGY"/> セッションの開始

いくつかの異なるエントリーポイントからセッションを開始できます。

* [github.com/copilot](<x id="RESR"/>)にある <x id="HGSN"/> <x id="4MAH"/> のホームページ。
* [https://github.com](<x id="HG4V"/>)にサインインしているときの <x id="N96X"/> <x id="QK7B"/> の個人用ダッシュボードまたは <x id="NCXC"/> のホームページ。
* リポジトリ内の **<x id="ZSX9"/> Agents** タブまたはパネル。

デフォルト設定のままプロンプトをすぐに送信することも、プロンプトを送信する前にタスクに合わせてセッションを設定することもできます。

1. プロンプトボックスに、<x id="X3ZD"/> に実行させたい内容を入力します。期待する結果と制約事項を含めてください。

   > [!TIP]
   > プロンプト内でスラッシュコマンドを使用して特定の操作を行うこともできます。たとえば、第2の意見を得るための <x id="9D3Y"/>、リポジトリの脆弱性をレビューするための <x id="GJP5"/>、セッションの使用状況情報を表示するための <x id="E7BR"/> などがあります。

1. 必要に応じて、**<x id="Q9WW"/> Attach** をクリックして <x id="FJF7"/> にリクエストの参照情報を提供します。

   **Files and folders**、**Upload from computer**、**Repository**、または **Space** を選択して、リクエストのコンテキストを提供します。

   クラウドサンドボックスセッションの場合は、コネクタや個人用のカスタム MCP サーバーを設定することで、サードパーティのソースから追加のコンテキストを提供できます。[AUTOTITLE](<x id="J423"/>)および[AUTOTITLE](<x id="CGKJ"/>)を参照してください。

1. **Mode** ピッカーを開き、<x id="JCYQ"/> とどのように連携するかを選択します。

   * **Interactive**: (デフォルト) <x id="5KR8"/> とステップバイステップで連携します。
   * **Autopilot**: エンドツーエンドの実行を <x id="NYJX"/> に委任します。

   同じメニューで、**Tool permissions** を使用してツールリクエストの承認方法を制御します。

   * **Assisted** (デフォルト) を選択します。安全性チェックを使用してリクエストを承認するかどうか、またはユーザーに確認するかを決定します。
   * **Always ask** を選択して、リクエストごとに承認を要求します。
   * **Allow all** を選択して、すべてのツール、パス、URL のリクエストを自動的に承認します。

1. **Models** ピッカーを開き、**Auto** (デフォルト) または特定モデルを選択します。モデルは、速度とコスト効率、汎用性と知性、または複雑なタスクの処理能力のいずれかを選択できるように、長所ごとにグループ化されています。選択したモデルが **Balance** などの設定可能な推論をサポートしている場合は、ドロップダウンメニューを使用して推論レベルを選択することもできます。

1. プロンプトボックスの下にある **Chat** セッションのコンテキストピッカーを使用して、セッションのスコープ (個人、組織、またはリポジトリ) を選択します。

   * 検索ボックスにリポジトリ名を入力して、追加するリポジトリを検索します。
   * **Ask anything across repositories** の下で **Chat** を選択し、リポジトリ横断で質問します。デフォルトのスコープは個人のリポジトリです。右側の画像をクリックしてアカウントメニューを開き、組織を選択するか、リポジトリの所有者 (ユーザーまたは組織) で検索してスコープを変更します。
   * **Work in a repository** の下で、作業を行う最近のリポジトリを選択します。リストされるリポジトリは、選択したスコープを反映しています。

   > [!NOTE]
   > * **Attach** メニュー (前のステップ) からリポジトリを追加すると、プロンプトの参照 (コンテキスト資料) が提供されます。一方、ここ **Start a session** の下でリポジトリを選択すると、そのリポジトリがセッションの作業用リポジトリ (スコープ) になります。セッションの開始時に、クラウドサンドボックスはそのリポジトリのコピーを取得し、既存の制約内でそのコンテンツを操作する権限を <x id="4NAJ"/> に与えます。
   > * リポジトリがリストに表示されない場合、個人設定、組織、またはエンタープライズポリシーによって <x id="V4VB"/> から除外されている可能性があります。

   任意で、上記でリポジトリを選択した場合、**main** (またはリストされているデフォルトブランチ名) をクリックして、<x id="FBW9"/> が作業コンテキストとして使用し、その内部で動作するブランチを選択することもできます。

<x id="RPNB"/>

1. **Send message** をクリックするか、<kbd>Enter</kbd> キーを押してプロンプトを送信し、セッションを開始します。

<x id="8D7A"/> はプロンプトに応答し、選択したコンテキストと環境に基づいてセッションを開始します。要求された場合、<x id="DG8B"/> は変更されたファイルのリスト、pull request、生成された成果物 (リサーチプランなど)、およびその他の関連する出力を生成します。

### ファイル、issue、または pull request 内からの <x id="D8Z5"/> の開始

コンテキストページから <x id="PTAQ"/> とのチャットセッションを開くと、セッションは開いているファイル、issue、または pull request のコンテキストから開始されます。

コンテキストパネル自体から新しいエージェントセッションを開始することはできません。<x id="XAW3"/> ページ、ホームページ、またはエージェントタブから開始する必要があります。

   リポジトリを指定しない場合、<x id="CCMJ"/> は issue と同じリポジトリで作業します。ブランチを指定しない場合、<x id="RJD5"/> は選択したリポジトリのデフォルトブランチから作業を行います。

   > [!TIP]
   > issue を <x id="ZXY9"/> に割り当てると、issue のタイトル、説明、既存のコメント、および提供した追加の指示が送信されます。issue を割り当てた後、<x id="W4AD"/> は issue に追加されたそれ以降のコメントを認識しないため、それに対して反応しません。詳細情報や元の要件からの変更がある場合は、<x id="7V3K"/> が作成する pull request のコメントとして追加してください。

## pull request での作業の継続

既存の pull request の変更やレビューコメントへの対応を <x id="8JXC"/> に依頼できます。その後、結果として得られるセッションを追跡し、フォローアップの指示を提供できます。

### 変更を <x id="8K9S"/> に依頼する

任意の pull request のコメント内で <x id="DVVF"/> をメンションすることで、変更を行うよう <x id="97B5"/> に依頼できます。これは、<x id="VRV6"/> によって作成された pull request や、あなたまたは他のユーザーが作成した pull request で機能します。

デフォルトでは、<x id="GPZX"/> は pull request ブランチに直接コミットをプッシュします。代わりに別の pull request を作成するには、コメントでその旨を説明してください。ブランチをチェックアウトして自分で変更をプッシュすることもできます。

<x id="EDHP"/> Web インターフェースから pull request のコメント (レビューやレビューコメントではない) を送信する場合は、モデルピッカーでモデルを選択します。<x id="4RAQ"/> はデフォルトで元の pull request のモデルを使用します。

### レビューコメントの委任

レビューコメントを委任して、人間のレビュアーや <x id="269H"/> からフィードバックを <x id="PQ8D"/> に実装させることができます。

1. pull request で **Files changed** タブを開きます。
1. <x id="KNYP"/> に実装させたい最初のレビューコメントに移動します。
   * 1つのコメントを委任するには、**Fix with <x id="MHZ4"/>** をクリックします。
   * 複数のコメントを委任するには、**Add to batch** をクリックします。作業させたいコメントを追加し続けます。
1. **Manage batch** パネルで追加の指示を追加し、必要に応じてモデルピッカーでモデルを選択します。
1. 変更をどのように適用するかを <x id="8Y3C"/> に選択させます。
   * 変更をブランチに直接コミットするには、**<x id="WJFJ"/> Fix and commit** をクリックします。
   * 変更を含む新しい pull request を <x id="3NJX"/> に作成させるには、ドロップダウンメニューから **Fix and open pull request** をクリックします。

### セッションの追跡と継続

## マージコンフリクトの解決

2つの方法で、pull request のマージコンフリクトを解決するように <x id="WABQ"/> に依頼できます。

* **「Fix with <x id="TAGT"/>」ボタンの使用**: pull request にマージコンフリクトがある場合は、マージボックスに表示される **Fix with <x id="KTZR"/>** ボタンをクリックします。
* **@copilot メンションの使用**: pull request のコメントで <x id="YCR9"/> をメンションし、コンフリクトを修正するように依頼します (例: 「@copilot resolve the merge conflicts on this PR」)。

<x id="XBBS"/> はコンフリクトしている変更を分析して解決し、ビルド、テスト、リンターが引き続き合格することを確認します。その後、マージする前に解決を確認できるようにレビューを依頼します。

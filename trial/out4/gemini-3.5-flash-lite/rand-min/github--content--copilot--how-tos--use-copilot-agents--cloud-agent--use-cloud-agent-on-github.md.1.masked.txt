## はじめに

⟦37JR⟧ セッションは、⟦6AQP⟧ 内のさまざまな場所から開始できます。セッションの実行が開始されると、ブラウザを離れることなく、その進捗状況の監視、フォローアッププロンプトによる誘導、結果として作成された pull request の反復作業を行うことができます。

⟦4TSV⟧ の詳細については、[AUTOTITLE](/copilot/concepts/copilot-surfaces/copilot-on-github) を参照してください。

⟦FN49⟧ を使用して、これらと同じエントリポイントからパートナーが構築したエージェントを開始することもできます。詳細については、[AUTOTITLE](/copilot/how-tos/use-copilot-agents/cloud-agent/use-agent-apps) を参照してください。

## ⟦KHWE⟧ セッションの開始

さまざまなエントリポイントからセッションを開始できます。

* ⟦github.com/copilot⟧(https://github.com/copilot?ref_product=copilot&ref_type=engagement&ref_style=text&utm_source=cloud-gh-docs-home-cta&utm_medium=docs&utm_campaign=universe-2026) にある ⟦JV26⟧ ⟦3EK4⟧ のホームページ。
* [https://github.com](https://github.com?ref_product=copilot&ref_type=engagement&ref_style=text) にサインインした状態での、⟦AW96⟧ ⟦5X8G⟧ のパーソナルダッシュボードまたは ⟦SPVB⟧ ホームページ。
* リポジトリ内の **⟦67JK⟧ Agents** タブまたはパネル。

デフォルト設定のまますぐにプロンプトを送信することも、プロンプトを送信する前にタスクに合わせてセッションを構成することもできます。

1. プロンプトボックスに、⟦QSKC⟧ に実行させたい内容を入力します。希望する結果と制約事項を含めてください。

   > [!TIP]
   > プロンプト内でスラッシュコマンドを使用して特定のアクションを実行することもできます。たとえば、第2の意見を得るための `/rubber-duck`、脆弱性のリポジトリレビューを行うための `/security-review`、セッションの使用状況情報を表示するための `/usage` などがあります。

1. オプションで、**⟦TFH6⟧ Attach** をクリックして、リクエストに対する参照を ⟦AXHG⟧ に提供します。

   リクエストのコンテキストを提供するには、**Files and folders**、**Upload from computer**、**Repository**、または **Space** を選択します。

   クラウドサンドボックスセッションの場合は、コネクタやパーソナルカスタム MCP サーバーを構成することで、サードパーティソースから追加のコンテキストを提供できます。[AUTOTITLE](/copilot/concepts/customizations/copilot-connectors) および [AUTOTITLE](/copilot/concepts/customizations/mcp#personal-mcp-servers) を参照してください。

1. **Mode** ピッカーを開いて、⟦TBWS⟧ とどのように連携するかを選択します。

   * **Interactive**: (デフォルト) ⟦VD7Q⟧ とステップバイステップで作業します。
   * **Autopilot**: エンドツーエンドの実行を ⟦WXE9⟧ に委任します。

   同じメニューで、**Tool permissions** を使用してツールリクエストの承認方法を制御します。

   * **Assisted** (デフォルト) を選択します。これは、安全チェックを使用してリクエストを承認するかどうか、またはユーザーに確認するかを決定します。
   * リクエストごとに承認を必須にするには **Always ask** を選択します。
   * すべてのツール、パス、および URL リクエストを自動的に承認するには **Allow all** を選択します。

1. **Models** ピッカーを開き、**Auto** (デフォルト) または特定モデルを選択します。モデルは、速度とコスト効率、汎用性と知能、または複雑なタスクの処理能力のいずれかを選択しやすくするために、その強みごとにグループ化されています。選択したモデルが **Balance** などの設定可能な推論をサポートしている場合は、ドロップダウンメニューを使用して推論レベルを選択することもできます。

1. プロンプトボックスの下部にある **Chat** セッションコンテキストピッカーを使用して、セッションのスコープ (個人、組織、またはリポジトリ) を選択します。

   * 検索ボックスにリポジトリ名を入力して、追加するリポジトリを検索します。
   * **Ask anything across repositories** の下にある **Chat** を選択して、複数のリポジトリにまたがって質問します。デフォルトのスコープは個人のリポジトリです。右側の画像をクリックしてアカウントメニューを開き、組織を選択するか、リポジトリオーナー (ユーザーまたは組織) で検索してスコープを変更します。
   * **Work in a repository** の下で、作業対象とする最近のリポジトリを選択します。リストされるリポジトリは、選択されたスコープを反映します。

   > [!NOTE]
   > * **Attach** メニュー (前のステップ) を介してリポジトリを追加すると、プロンプトの参照 (コンテキスト資料) が提供されます。一方、ここで **Start a session** の下で選択すると、そのリポジトリがセッションの作業リポジトリ (スコープ) になります。セッションの開始時に、クラウドサンドボックスはそのリポジトリのコピーを取得し、既存の制約の範囲内でそのコンテンツを操作する権限を ⟦DAEC⟧ に付与します。
   > * リポジトリがリストに表示されない場合は、個人設定、組織、またはエンタープライズポリシーによって ⟦R5Z8⟧ から除外されている可能性があります。

   オプションで、上記でリポジトリを選択した場合、⟦9M7F⟧ が作業コンテキストとして使用し、その中で操作を行うブランチを選択するために **main** (またはリストされているデフォルトブランチ名) をクリックすることもできます。

⟦DA4D⟧

1. **Send message** をクリックするか、<kbd>Enter</kbd> キーを押してプロンプトを送信し、セッションを開始します。

⟦T432⟧ はプロンプトに応答し、選択されたコンテキストと環境に基づいてセッションを開始します。要求された場合、⟦ZNEY⟧ は変更されたファイルのリスト、pull request、生成された成果物 (リサーチプランなど)、およびその他の関連出力を生成します。

## pull request での作業の継続

既存の pull request に対する変更やレビューコメントへの対応を ⟦MQW5⟧ に依頼できます。その後、結果のセッションを追跡し、フォローアップの指示を提供できます。

### ⟦EVCS⟧ に変更を依頼する

任意の pull request のコメントで `@copilot` をメンションして、⟦MP4K⟧ に変更を依頼できます。これは、⟦7MNA⟧ によって作成された pull request や、あなたや他の人が作成した pull request で機能します。

デフォルトでは、⟦WKHM⟧ は pull request ブランチに直接コミットをプッシュします。代わりに個別の pull request を作成するには、その旨をコメントに記述します。ブランチをチェックアウトして自分で変更をプッシュすることもできます。

⟦66Q4⟧ Web インターフェイスから pull request のコメント (レビューやレビューコメントではない) を送信する場合は、モデルピッカーでモデルを選択します。⟦HN5Q⟧ はデフォルトで元の pull request のモデルを使用します。

### レビューコメントの委任

レビューコメントを委任して、人間のレビュアーや ⟦85TD⟧ からのフィードバックを ⟦4VY4⟧ に実装させることができます。

1. pull request で、**Files changed** タブを開きます。
2. ⟦2CTZ⟧ に実装させたい最初のレビューコメントに移動します。
   * 1つのコメントを委任するには、**Fix with ⟦35P9⟧** をクリックします。
   * 複数のコメントを委任するには、**Add to batch** をクリックします。作業させたいコメントを追加し続けます。
3. **Manage batch** パネルで、追加の指示を追加し、オプションでモデルピッカーでモデルを選択します。
4. ⟦435W⟧ に変更を適用する方法を選択します。
   * 変更をブランチに直接コミットするには、**⟦WD7Y⟧ Fix and commit** をクリックします。
   * 変更を加えた新しい pull request を ⟦YDE8⟧ に作成させるには、ドロップダウンメニューから **Fix and open pull request** をクリックします。

## マージコンフリクトの解決

2つの方法で、pull request のマージコンフリクトを解決するように ⟦GYQT⟧ に依頼できます。

* **「Fix with ⟦7SEC⟧」ボタンの使用**: pull request にマージコンフリクトがある場合は、マージボックスに表示される **Fix with ⟦AKC8⟧** ボタンをクリックします。
* **@copilot メンションの使用**: pull request のコメント内で `@copilot` をメンションし、コンフリクトの修正を依頼します (例: "@copilot resolve the merge conflicts on this PR.")。

⟦9ATA⟧ はコンフリクトしている変更を分析し、それらを解決して、ビルド、テスト、およびリンターが引き続き合格することを確認します。その後、マージする前に解決を確認できるように、レビューを依頼します。

2. 親指を下げるボタンをクリックした場合は、オプションで理由を選択してコメントを残し、**Submit feedback** をクリックします。

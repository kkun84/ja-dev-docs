## はじめに

<x id="37JR"/> セッションは <x id="6AQP"/> のさまざまな場所から開始できます。セッションが実行されたら、その進捗を監視し、フォローアップのプロンプトで指示を与え、ブラウザを離れることなく生成された pull request を反復して修正できます。

<x id="4TSV"/> の詳細については、[AUTOTITLE](<x id="RQXK"/>) を参照してください。

また、<x id="FN49"/> を使用して、これらと同じエントリーポイントからパートナーが構築したエージェントを開始することもできます。詳細については、[AUTOTITLE](<x id="FQVM"/>) を参照してください。

## <x id="KHWE"/> セッションの開始

セッションは、いくつかの異なるエントリーポイントから開始できます。

* [github.com/copilot](<x id="YEQZ"/>) にある <x id="JV26"/> <x id="3EK4"/> のホームページ。
* [https://github.com](<x id="FBHR"/>) にサインインした状態での、<x id="AW96"/> <x id="5X8G"/> の個人用ダッシュボードまたは <x id="SPVB"/> ホームページ。
* リポジトリ内の **<x id="67JK"/> Agents** タブまたはパネル。

デフォルト設定でプロンプトをすぐに送信することも、プロンプトを送信する前にタスクに合わせてセッションを設定することもできます。

1. プロンプトボックスに、<x id="QSKC"/> に実行させたい内容を入力します。希望する結果と制約事項を含めてください。

   > [!TIP]
   > プロンプト内でスラッシュコマンドを使用して、2番目の意見を求める <x id="FB4N"/>、リポジトリの脆弱性をレビューする <x id="B473"/>、セッションの使用状況情報を表示する <x id="J5D2"/> など、特定のアクションを実行することもできます。

1. オプションで **<x id="TFH6"/> Attach** をクリックして、<x id="AXHG"/> にリクエストの参照情報を提供します。

   **Files and folders**、**Upload from computer**、**Repository**、または **Space** を選択して、リクエストのコンテキストを提供します。

   クラウドサンドボックスセッションの場合は、コネクタや個人のカスタム MCP サーバーを設定することで、サードパーティのソースから追加のコンテキストを提供できます。[AUTOTITLE](<x id="BFDW"/>) および [AUTOTITLE](<x id="7KSK"/>) を参照してください。

1. **Mode** ピッカーを開いて、<x id="TBWS"/> とどのようにコラボレーションするかを選択します。

   * **Interactive**: （デフォルト）<x id="VD7Q"/> とステップバイステップで作業します。
   * **Autopilot**: エンドツーエンドの実行を <x id="WXE9"/> に委任します。

   同じメニューで、**Tool permissions** を使用してツールリクエストの承認方法を制御します。

   * **Assisted**（デフォルト）を選択します。安全チェックを使用して、リクエストを承認するかユーザーに確認するかを決定します。
   * **Always ask** を選択して、リクエストごとに承認を必須にします。
   * **Allow all** を選択して、すべてのツール、パス、および URL のリクエストを自動的に承認します。

1. **Models** ピッカーを開き、**Auto**（デフォルト）または特定モデルを選択します。モデルは、速度と費用対効果、汎用性と知性、または複雑なタスクへの適性の間で選択しやすくなるように、その長所ごとにグループ化されています。選択したモデルが **Balance** などの設定可能な推論をサポートしている場合は、ドロップダウンメニューを使用して推論レベルを選択することもできます。

1. プロンプトボックスの下部にある **Chat** セッションコンテキストピッカーを使用して、セッションのスコープ（個人、組織、またはリポジトリ）を選択します。

   * 検索ボックスに追加するリポジトリ名を入力してリポジトリを検索します。
   * **Ask anything across repositories** の下にある **Chat** を選択して、リポジトリ横断的に質問します。デフォルトのスコープは個人用リポジトリです。右側の画像をクリックしてアカウントメニューを開き、組織を選択するか、リポジトリ所有者（ユーザーまたは組織）で検索してスコープを変更します。
   * **Work in a repository** の下で、作業を行う最近のリポジトリを選択します。リストされるリポジトリは、選択したスコープを反映します。

   > [!NOTE]
   > * **Attach** メニュー（前のステップ）からリポジトリを追加すると、プロンプトの参照（コンテキスト資料）が提供されます。一方、ここで **Start a session** の下で選択すると、そのリポジトリがセッションの作業用リポジトリ（スコープ）になります。セッションの開始時に、クラウドサンドボックスがリポジトリのコピーを作成し、既存の制約内でそのコンテンツを操作する権限を <x id="DAEC"/> に与えます。
   > * リポジトリがリストに表示されない場合、個人設定、組織、またはエンタープライズポリシーによって <x id="R5Z8"/> から除外されている可能性があります。

   オプションで、上記でリポジトリを選択した場合は、**main**（またはリストされているデフォルトブランチ名）をクリックして、<x id="9M7F"/> が作業コンテキストとして使用し、その中で操作を行うブランチを選択することもできます。

<x id="DA4D"/>

1. **Send message** をクリックするか、<kbd>Enter</kbd> キーを押してプロンプトを送信し、セッションを開始します。

<x id="T432"/> は、選択されたコンテキストと環境に基づいて、プロンプトに応答し、セッションを開始します。要求された場合、<x id="ZNEY"/> は、変更されたファイルのリスト、pull request、生成された成果物（調査計画など）、およびその他の関連する出力を生成します。

### ファイル、issue、または pull request 内からの <x id="7D3S"/> の開始

コンテキストページから <x id="XC9Y"/> とのチャットセッションを開くと、セッションは開いているファイル、issue、または pull request のコンテキストから始まります。

コンテキストパネル自体の中から新しいエージェントセッションを開始することはできません。<x id="PCNS"/> ページ、ホームページ、またはエージェントタブから開始する必要があります。

## pull request での作業の継続

既存の pull request の変更やレビューコメントへの対応を <x id="MQW5"/> に依頼できます。その後、結果のセッションを追跡し、フォローアップの指示を提供できます。

### 変更の依頼を <x id="EVCS"/> に行う

任意の pull request のコメントで <x id="TSYM"/> をメンションして、<x id="MP4K"/> に変更を依頼できます。これは、<x id="7MNA"/> が作成した pull request や、あなたや他の人が作成した pull request で機能します。

デフォルトでは、<x id="WKHM"/> は pull request ブランチに直接コミットをプッシュします。代わりに別の pull request を作成するには、その旨をコメントに記述します。また、自分でブランチをチェックアウトして変更をプッシュすることもできます。

<x id="66Q4"/> の Web インターフェースから pull request のコメント（レビューやレビューコメントではない）を送信する場合は、モデルピッカーでモデルを選択します。<x id="HN5Q"/> はデフォルトで元の pull request のモデルを使用します。

### レビューコメントの委任

レビューコメントを委任して、人間のレビュアーや <x id="85TD"/> からのフィードバックを <x id="4VY4"/> に実装させることができます。

1. pull request で **Files changed** タブを開きます。
2. <x id="2CTZ"/> に実装させたい最初のレビューコメントに移動します。
   * 1つのコメントを委任するには、**Fix with <x id="35P9"/>** をクリックします。
   * 複数のコメントを委任するには、**Add to batch** をクリックします。<x id="2M26"/> に作業させたいコメントを追加し続けます。
3. **Manage batch** パネルで、追加の指示を追加し、必要に応じてモデルピッカーでモデルを選択します。
4. <x id="435W"/> に変更を適用する方法を選択します。
   * 変更をブランチに直接コミットするには、**<x id="WD7Y"/> Fix and commit** をクリックします。
   * 変更を加えた新しい pull request を <x id="YDE8"/> に作成させるには、ドロップダウンメニューから **Fix and open pull request** をクリックします。

## マージコンフリクトの解決

次の2つの方法のいずれかで、pull request のマージコンフリクトを解決するよう <x id="GYQT"/> に依頼できます。

* **「Fix with <x id="7SEC"/>」ボタンの使用**: pull request にマージコンフリクトがある場合は、マージボックスに表示される **Fix with <x id="AKC8"/>** ボタンをクリックします。
* **@copilot メンションの使用**: pull request のコメントで <x id="XRBK"/> をメンションし、コンフリクトを修正するよう依頼します（例：「@copilot resolve the merge conflicts on this PR」）。

<x id="9ATA"/> はコンフリクトしている変更を分析して解決し、ビルド、テスト、およびリンターが引き続き合格することを確認します。その後、マージする前に解決を確認できるようにレビューを依頼します。

## <x id="GDA2"/> を使用した <x id="YJM9"/> の自動実行

スケジュールに沿って、または issue が開かれるなどのイベントに応答して、<x id="8JKN"/> が <x id="AYMN"/> を自動的に実行するように設定できます。<x id="EYP3"/> は、リポジトリの **Agents** タブにある **<x id="WXFK"/>** ペインから作成および管理します。詳細については、[AUTOTITLE](<x id="THFT"/>) を参照してください。

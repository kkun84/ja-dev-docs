## はじめに

GitHub上のさまざまな場所から、クラウドでの GitHub Copilot セッションを開始できます。セッションが実行されたら、その進捗を監視し、フォローアップのプロンプトで指示を与え、ブラウザを離れることなく結果のpull requestを反復修正できます。

クラウドでの Copilot の詳細については、[AUTOTITLE](⟦5Z46⟧) をご覧ください。

また、エージェントアプリを使用して、これらと同じエントリーポイントからパートナー製のエージェントを開始することもできます。詳細については、[AUTOTITLE](⟦QGQY⟧) をご覧ください。

## クラウドでの Copilot セッションの開始

いくつかの異なるエントリーポイントからセッションを開始できます。

* [github.com/copilot](⟦AH3N⟧) にある Copilot ⟦37JR⟧ のホームページ。
* [https://github.com](⟦F9BJ⟧) にサインインしているときの ⟦6AQP⟧ GitHub パーソナルダッシュボードまたは ⟦4TSV⟧ ホームページ。
* リポジトリ内の **⟦FN49⟧ Agents** タブまたはパネル。

デフォルト設定のままですぐにプロンプトを送信することも、プロンプトを送信する前にタスクに合わせてセッションを設定することもできます。

1. プロンプトボックスに、Copilotに実行させたい内容を入力します。望む結果と制約事項を含めてください。

   > [!TIP]
   > プロンプト内でスラッシュコマンドを使用して、セカンドオピニオンを得るための ⟦PCNS⟧、脆弱性がないかリポジトリをレビューするための ⟦BDZS⟧、セッションの使用状況情報を表示するための ⟦CN45⟧ などの特定のアクションを実行することもできます。

1. オプションで、**⟦KHWE⟧ Attach** をクリックして、リクエスト用の参照情報をCopilotに提供します。

   リクエストのコンテキストを提供するには、**Files and folders**、**Upload from computer**、**Repository**、または **Space** を選択します。

   クラウドサンドボックスセッションの場合、コネクタや個人のカスタムMCPサーバーを設定することで、サードパーティのソースから追加のコンテキストを提供できます。[AUTOTITLE](⟦6DF7⟧) と [AUTOTITLE](⟦AN9V⟧) をご覧ください。

1. **Mode** ピッカーを開いて、Copilotとどのように連携するかを選択します。

   * **Interactive**: (デフォルト) Copilotとステップバイステップで作業します。
   * **Autopilot**: タスクをCopilotに委任し、エンドツーエンドで実行させます。

   同じメニューで、**Tool permissions** を使用してツールリクエストの承認方法を制御します。

   * **Assisted** (デフォルト) を選択します。これは安全チェックを使用して、リクエストを承認するかユーザーに尋ねるかを決定します。
   * **Always ask** を選択して、リクエストごとに承認を必須にします。
   * **Allow all** を選択して、すべてのツール、パス、URLのリクエストを自動的に承認します。

1. **Models** ピッカーを開き、**Auto** (デフォルト) または特定のモデルを選択します。モデルは、速度とコスト効率、汎用性と知能、または複雑なタスクの処理能力のいずれかを選択できるように、その長所ごとにグループ化されています。選択したモデルが **Balance** などの設定可能な推論をサポートしている場合は、ドロップダウンメニューを使用して推論レベルを選択することもできます。

1. プロンプトボックスの下にある **Chat** セッションコンテキストピッカーを使用して、セッションのスコープ (個人、組織、またはリポジトリ) を選択します。

   * 検索ボックスにリポジトリ名を入力して、追加するリポジトリを検索します。
   * **Ask anything across repositories** の下にある **Chat** を選択して、リポジトリを横断して質問します。デフォルトのスコープは個人のリポジトリです。右側の画像をクリックしてアカウントメニューを開き、組織を選択するか、リポジトリの所有者 (ユーザーまたは組織) で検索してスコープを変更します。
   * **Work in a repository** の下で、作業を行う最近のリポジトリを選択します。リストされるリポジトリは、選択したスコープを反映しています。

   > [!NOTE]
   > * **Attach** メニュー (前のステップ) からリポジトリを追加すると、プロンプトの参照資料 (コンテキスト素材) が提供されます。一方、ここで **Start a session** の下でリポジトリを選択すると、そのリポジトリがセッションの作業リポジトリ (スコープ) になります。セッションの開始時に、クラウドサンドボックスはリポジトリのコピーを作成し、既存の制約の範囲内でそのコンテンツを操作する権限をCopilotに与えます。
   > * リポジトリがリストされない場合、個人の設定、あるいは組織やエンタープライズのポリシーによってCopilotから除外されている可能性があります。

   オプションで、上記でリポジトリを選択している場合、**main** (またはリストされているデフォルトブランチ名) をクリックして、Copilotが作業コンテキストとして使用し、その中で操作を行うブランチを選択することもできます。

⟦JV26⟧

1. **Send message** をクリックするか、<kbd>Enter</kbd> キーを押してプロンプトを送信し、セッションを開始します。

Copilotはプロンプトに応答し、選択したコンテキストと環境に基づいてセッションを開始します。要求された場合、Copilotは変更されたファイルのリスト、pull request、生成された成果物 (リサーチプランなど)、およびその他の関連する出力を生成します。

### ファイル、issue、またはpull request内からのCopilotの起動

コンテキストページからCopilotとのチャットセッションを開くと、セッションは、開いているファイル、issue、またはpull requestのコンテキストを引き継いで開始されます。

コンテキストパネル内から直接新しいエージェントセッションを開始することはできません。Copilotページ、ホームページ、またはエージェントタブから開始する必要があります。

## 失敗したGitHub Actionsワークフロー実行の修正

1. **⟦T432⟧ Fix with Copilot** ボタンをクリックします。

   Copilotによって新しいセッションが開始され、失敗の原因が調査され、ブランチに修正がプッシュされます。

## pull requestでの作業の継続

既存のpull requestに対して、変更の加えたりレビューコメントに対処したりするようCopilotに依頼できます。その後、結果のセッションを追跡し、フォローアップの指示を提供できます。

### Copilotへの変更の依頼

任意のpull requestのコメント内で ⟦MAXD⟧ をメンションして、Copilotに変更を加えるよう依頼できます。これは、Copilotが作成したpull requestや、あなたや他のユーザーが作成したpull requestで機能します。

デフォルトでは、Copilotはpull requestのブランチに直接コミットをプッシュします。代わりに別のpull requestを作成するには、その旨をコメントで説明します。自分でブランチをチェックアウトして変更をプッシュすることもできます。

GitHub Webインターフェースからpull requestのコメント (レビューやレビューコメントではない) を送信する場合は、モデルピッカーでモデルを選択します。Copilotはデフォルトで元のpull requestのモデルを使用します。

### レビューコメントの委任

レビューコメントを委任して、人間のレビューアやGitHub CopilotコードレビューからのフィードバックをCopilotに実装させることができます。

1. pull requestで、**Files changed** タブを開きます。
1. Copilotに実装させたい最初のレビューコメントに移動します。
   * 1つのコメントを委任するには、**Fix with Copilot** をクリックします。
   * 複数のコメントを委任するには、**Add to batch** をクリックします。Copilotに作業させたいコメントを追加し続けます。
1. **Manage batch** パネルで、追加の指示を追加し、必要に応じてモデルピッカーでモデルを選択します。
1. Copilotに変更を適用する方法を選択します。
   * 変更をブランチに直接コミットするには、**⟦ZNEY⟧ Fix and commit** をクリックします。
   * 変更を加えた新しいpull requestをCopilotに作成させるには、ドロップダウンメニューから **Fix and open pull request** をクリックします。

## マージコンフリクトの解決

pull requestのマージコンフリクトを解決するようにCopilotに依頼するには、2つの方法があります。

* **「Fix with Copilot」ボタンの使用**: pull requestにマージコンフリクトがある場合は、マージボックスに表示される **Fix with Copilot** ボタンをクリックします。
* **@copilot メンションの使用**: pull requestのコメント内で ⟦JH29⟧ をメンションし、コンフリクトの修正を依頼します (例: 「@copilot resolve the merge conflicts on this PR.」)。

Copilotはコンフリクトしている変更を分析して解決し、ビルド、テスト、およびリンターが引き続き合格することを確認します。その後、マージする前に解決を確認できるように、あなたにレビューを要求します。

## Copilotの作業に対するフィードバックの提供

Copilotのpull requestやコメントにあるフィードバックボタンを使用して、出力を評価します。フィードバックはCopilotの品質向上に役立ちます。

1. Copilotのpull requestまたはコメントで、サムズアップ (:+1:) またはサムズダウン (:-1:) ボタンをクリックします。
1. サムズダウンボタンをクリックした場合は、オプションで理由を選択してコメントを残し、**Submit feedback** をクリックします。

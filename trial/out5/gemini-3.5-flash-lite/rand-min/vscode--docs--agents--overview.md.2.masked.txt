# Build with AI in VS Code

Visual Studio Code では、タスクのニーズに合わせて、必要なだけ AI を活用できます。入力に応じたサジェストを受け取る、コード・テスト・デバッガーの横でエージェントと共同作業を行う、または Agents ウィンドウでプロジェクトを横断してタスクを調整します。作業の進捗に合わせて、これらのアプローチを組み合わせることができます。

複数のプロバイダーからモデルを選択し、サポートされているアカウントまたは独自の API キーを使用して、Copilot、Claude、または Codex のエージェントハーネスを利用して作業します。ハーネスは、モデル周辺のツールとワークフローを提供します。カスタマイズやプラグインにより、作業に合わせてエージェントを調整できます。

Continuity 機能により、最初からやり直すことなく、サポートされているインターフェイス間でエージェントの作業を引き継ぐことができます。GitHub 環境を通じて自分のマシンのセッションに接続するか、ローカルのホストをオンラインに維持せずにクラウドセッションを使用します。

[エージェント](/docs/agents/concepts/agents.md)はモデルとツールを使用して、関連するコードの検索、変更の実行、およびチェックの実行を行います。Chat ビューと Agents ウィンドウの両方でエージェントが実行されます。目標を設定し、作業を誘導し、結果を確認します。

日常的な作業では、プロンプトを[自動化 (automation)](/docs/agents/run/automations.md)として保存します。ローカルでスケジュール実行するか、クラウド自動化 `feature(cloud-automations)` を使用して、コンピュータの電源がオフの間も継続するスケジュール実行やイベント駆動型のリポジトリ作業を行います。定期的な作業を有効にする前に、手動での実行を確認してください。

特定の編集には、コードから離れることなく[インラインチャット](/docs/chat/inline-chat.md)を使用します。特定のタスクの機能を比較するには、[AI 機能チートシート](/docs/agents/reference/ai-features-cheat-sheet.md#choose-a-feature)を使用します。

## モデル、エージェント、およびツールの選択

最初のエージェントタスクでは、すべてのオプションを設定せずに[クイックスタートを使用します](/docs/agents/quickstart.md)。ニーズの変化に応じて、以下の選択肢を適宜調整できます。

| 選択肢 | オプション |
|--------|---------|
| **モデル** | GitHub Copilot を通じて[複数のプロバイダーのモデルを選択](/docs/agent-customization/language-models.md)するか、独自の [API キー (BYOK)](/docs/agent-customization/language-models.md#bring-your-own-language-model-key) またはサポートされているローカルモデルを使用します。 |
| **エージェントハーネス** | [ツールとワークフロー](/docs/agents/run/agent-harnesses.md#compare-agent-harnesses)に基づいて、Copilot、Claude、または Codex から選択します。 |
| **アクセスと課金** | 既存の GitHub Copilot プラン、サポートされているプロバイダーアカウント、または API キーを使用します。[ハーネスの要件](/docs/agents/run/agent-harnesses.md#requirements-and-setup)を確認してください。 |
| **カスタマイズ** | [プラグイン](/docs/agent-customization/agent-plugins.md)、[プロジェクト指示](/docs/agents/guides/customize-copilot-guide.md)、[スキル](/docs/agent-customization/agent-skills.md)を使用してエージェントを調整します。[Model Context Protocol (MCP) サーバー](/docs/agent-customization/mcp-servers.md)を介して外部ツールを接続します。 |

## インターフェイスとマシン間での継続

Continuity とは、最初からやり直すことなく、サポートされているインターフェイスやマシン間でエージェントの作業を引き継ぐことを意味します。ワークスペースと実行環境をホスト側に維持したまま、エージェントと対話する場所を選択します。セッションのサポート内容と要件は、ハーネスや宛先によって異なります。

| 作業を行いたい場所 | ここから開始 |
|------------------------|------------|
| **Copilot アプリとデバイス間** | [GitHub 環境](/docs/agents/run/remote-agent-sessions.md#github-environments) `feature(github-environments)` を使用して開発マシンを登録し、VS Code、GitHub Copilot アプリ、Copilot CLI、GitHub.com、または GitHub Mobile からエージェントセッションを継続します。利用可能なアクションはクライアントによって異なります。 |
| **管理されたクラウドコンピュート上** | [クラウドセッション](/docs/agents/run/cloud-sandbox-sessions.md) `feature(cloud-sessions)` を使用すると、自身のマシンの電源を入れたままにしなくても、インタラクティブなエージェント作業を行えます。既存のクラウドセッションを再度開いて会話を続行します。実行はクラウド環境内で行われ、その可用性とライフタイムはサービスによって管理されます。 |
| **エディターまたは Agents ウィンドウ** | VS Code で GitHub Copilot、Claude、または Codex エージェントハーネスを使用し、[インターフェイス間でセッションを継続します](/docs/agents/run/sessions/manage-sessions.md#continue-between-the-chat-view-and-agents-window)。 |
| **別マシンの VS Code** | [SSH](/docs/agents/run/remote-agent-sessions.md#connect-via-ssh) または[開発用トンネル](/docs/agents/run/remote-agent-sessions.md#connect-via-dev-tunnel)を介した VS Code 固有のリモート接続を使用します。開発用トンネルは、[ブラウザーベースの Agents ウィンドウ](/docs/agents/run/remote-agent-sessions.md#use-the-agents-window-in-the-browser)もサポートしています。 |

自身のマシンで実行されるセッションについては、ホストを稼働状態にしてアクセス可能な状態に維持してください。クラウドセッションでは、代わりに管理されたコンピュートを使用します。クラウドでの作業のためにクラウドセッションを開始し、後からそのセッションを再び開いて作業を続行します。

自身のプライベートリポジトリを使用して、[VS Code でクラウドエージェントタスクを開始し、Copilot CLI でそれを継続します](/docs/agents/cloud-continuity-tutorial.md) (実験的)。

ツールが実行される場所とモデルがホストされている場所は、個別に選択できます。エージェントは、ホストされているプロバイダーにモデルリクエストを送信しながら、マシン上のファイルを編集できます。

## 制御の維持

AI は、不正確なコード生成や意図の誤解を生む可能性があります。どの変更をコードベースに取り入れるかの最終的な責任はユーザーが負います。

* **統合前のレビュー。** エージェントは、編集内容をセッションフォルダーやワークツリーに直接保存できます。変更をコミットまたはマージする前に、[差分を確認して結果を検証](/docs/agents/run/review-code-edits.md)してください。
* **アクションの制御と作業の誘導。** [権限と承認](/docs/agents/run/approvals.md)を使用して、どのアクションに確認が必要かを決定します。[リクエストの誘導や停止](/docs/chat/chat-overview.md#send-messages-while-a-request-is-running)を行うことはできますが、停止しても、完了したアクションや外部サービスへの変更は取り消されません。
* **分離の理解。** Git ワークツリーによってコードの変更は分離されますが、セキュリティ境界にはなりません。エージェントが実行するターミナルコマンドに対するファイルシステムやネットワークの制限については、[プラットフォーム固有のサンドボックスオプション](/docs/agents/run/agent-sandboxing.md)を確認してください。

既存のプロジェクトでエージェントを使用する前に、[推奨されるセキュリティベースライン](/docs/agents/run/security.md#recommended-security-baseline)を確認してください。管理されたデバイスでは、組織によって利用可能なエージェント、モデル、ツールが[エンタープライズ AI ポリシー](/docs/enterprise/manage-ai-settings.md)を通じて制限されている場合があります。チャットにエージェントが表示されない場合は、[可用性のトラブルシューティング手順](/docs/agents/agent-troubleshooting/faq.md#agents-are-not-available-in-chat)を確認してください。

キーボード、スクリーンリーダー、およびロービジョン向けのワークフローについては、[アクセシブルビューおよびその他のユーザー補助機能](/docs/configure/accessibility/accessibility.md#accessible-view)の使用方法を参照してください。

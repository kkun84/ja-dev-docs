## はじめに

⟦ZJ6Q⟧上のさまざまな場所から ⟦8ZCQ⟧ セッションを開始できます。セッションが実行されたら、ブラウザから離れることなく、その進捗を監視したり、追加プロンプトで誘導したり、結果として作成された pull request を反復的に修正したりできます。

⟦EZZR⟧ の詳細については、[AUTOTITLE](⟦TEPX⟧) を参照してください。

また、⟦WQCF⟧ を使用して、これらと同じエントリポイントからパートナーが構築したエージェントを開始することもできます。詳細については、[AUTOTITLE](⟦4H2R⟧) を参照してください。

## ⟦RD4J⟧ セッションの開始

いくつかの異なるエントリポイントからセッションを開始できます。

* [github.com/copilot](⟦RADB⟧) にある ⟦V46C⟧ ⟦NFP4⟧ のホームページ。
* [https://github.com](⟦FW4F⟧) にサインインした状態の ⟦MSF9⟧ ⟦89WG⟧ のパーソナルダッシュボードまたは ⟦KRTD⟧ ホームページ。
* リポジトリ内の **⟦8GCX⟧ Agents** タブまたはパネル。

デフォルト設定のままプロンプトをすぐに送信することも、プロンプトを送信する前にタスクに合わせてセッションを設定することもできます。

1. プロンプトボックスに、⟦4CJN⟧ に実行させたい内容を入力します。希望する成果と制約事項を含めてください。

   > [!TIP]
   > また、プロンプト内でスラッシュコマンドを使用して特定のアクションを実行することもできます。たとえば、第2の意見を得るには ⟦6AQ6⟧ を、リポジトリの脆弱性をレビューするには ⟦KJDE⟧ を、セッションの使用状況情報を表示するには ⟦MWBT⟧ を使用します。

1. 必要に応じて、**⟦6R44⟧ Attach** をクリックして ⟦HTB9⟧ にリクエストの参照を提供します。

   リクエストのコンテキストを提供するには、**Files and folders**、**Upload from computer**、**Repository**、または **Space** を選択します。

   クラウドサンドボックスセッションの場合、コネクタや個人のカスタム MCP サーバーを設定することで、サードパーティソースからの追加コンテキストを提供できます。[AUTOTITLE](⟦PJ9K⟧) および [AUTOTITLE](⟦VETP⟧) を参照してください。

1. **Mode** ピッカーを開き、⟦VW66⟧ とどのように共同作業を行うかを選択します。

   * **Interactive**: （デフォルト）⟦ATFC⟧ と段階的に作業を進めます。
   * **Autopilot**: エンドツーエンドの実行を ⟦35TG⟧ に委任します。

   同じメニューで、**Tool permissions** を使用してツールリクエストの承認方法を制御します。

   * **Assisted** （デフォルト）を選択します。これは安全チェックを使用して、リクエストを承認するかユーザーに確認するかを決定します。
   * リクエストごとに承認を求めるには **Always ask** を選択します。
   * すべてのツール、パス、および URL リクエストを自動的に承認するには **Allow all** を選択します。

1. **Models** ピッカーを開き、**Auto** （デフォルト）または特定のモデルを選択します。モデルは、速度とコスト効率、汎用性と知性、または複雑なタスクへの適性のいずれかを選択しやすくするために、それぞれの長所ごとにグループ化されています。選択したモデルが **Balance** などの設定可能な推論をサポートしている場合は、ドロップダウンメニューを使用して推論レベルを選択することもできます。

1. プロンプトボックスの下にある **Chat** セッションコンテキストピッカーを使用して、セッションのスコープ（個人、組織、またはリポジトリ）を選択します。

   * 検索ボックスにリポジトリ名を入力して、追加するリポジトリを検索します。
   * **Ask anything across repositories** の下で **Chat** を選択し、リポジトリ横断で質問します。デフォルトのスコープは個人のリポジトリです。右側の画像をクリックしてアカウントメニューを開き、組織を選択するか、リポジトリオーナー（ユーザーまたは組織）で検索してスコープを変更します。
   * **Work in a repository** の下で、作業を行う最近のリポジトリを選択します。リストされるリポジトリは、選択されたスコープを反映します。

   > [!NOTE]
   > * **Attach** メニュー（前のステップ）からリポジトリを追加すると、プロンプトの参照（コンテキスト素材）が提供されます。一方、ここで **Start a session** の下でリポジトリを選択すると、そのリポジトリがセッションの作業リポジトリ（スコープ）になります。セッションの開始時に、クラウドサンドボックスはリポジトリのコピーを作成し、既存の制約内でそのコンテンツを操作する権限を ⟦MPJA⟧ に与えます。
   > * リポジトリがリストに表示されない場合、個人設定、組織、またはエンタープライズポリシーによって ⟦8Z7P⟧ から除外されている可能性があります。

   任意で、上記でリポジトリを選択した場合、⟦QS2Y⟧ が作業コンテキストとして使用しその中で動作するブランチを選択するために、**main** （またはリストされているデフォルトのブランチ名）をクリックすることもできます。

⟦G2DP⟧

1. **Send message** をクリックするか、<kbd>Enter</kbd> キーを押してプロンプトを送信し、セッションを開始します。

⟦RYT9⟧ はプロンプトに応答し、選択されたコンテキストと環境に基づいてセッションを開始します。要求された場合、⟦HRDP⟧ は変更されたファイルのリスト、pull request、生成した成果物（リサーチプランなど）、およびその他の関連する出力を生成します。

## pull request での作業の継続

既存の pull request に対して変更を行ったり、レビューコメントに対応したりするよう ⟦M9KF⟧ に依頼できます。その後、結果のセッションを追跡し、後続の指示を提供できます。

### 変更を ⟦VCRF⟧ に依頼する

任意の pull request のコメント内で ⟦HP63⟧ をメンションして、⟦PM6F⟧ に変更を加えるよう依頼できます。これは、⟦5VMA⟧ が作成した pull request や、あなたや他のユーザーが作成した pull request で機能します。

⟦GVAP⟧ Web インターフェースから pull request のコメント（レビューやレビューコメントではない）を送信する場合は、モデルピッカーでモデルを選択します。⟦XVHX⟧ はデフォルトで元の pull request のモデルを使用します。

# VS CodeでのAIを活用したビルド

Visual Studio Codeでは、タスクに必要なだけ、または必要な範囲でAIを活用できます。入力に応じたサジェスチョンの取得、コード、テスト、デバッガーの横でのエージェントとの共同作業、またはAgentsウィンドウでのプロジェクトをまたいだタスクの調整が可能です。作業の変化に合わせて、これらのアプローチを組み合わせることができます。

複数のプロバイダーからモデルを選択し、サポートされているアカウントまたは独自のAPIキーを使用して、Copilot、Claude、またはCodexのエージェントハーネスを操作できます。ハーネスは、モデルの周囲にあるツールとワークフローを提供します。カスタマイズやプラグインにより、作業に合わせてエージェントを調整できます。

Continuity（継続性）機能を使用すると、最初からやり直すことなく、サポートされているインターフェイス間でエージェントの作業を引き継ぐことができます。GitHub環境を通じて自分のマシンのセッションに接続するか、ローカルのホストをオンラインに保たずにクラウドセッションを使用します。

[エージェント](⟦P6RN⟧)は、モデルとツールを使用して関連コードの検索、変更の実行、およびチェックを行います。ChatビューとAgentsウィンドウの両方でエージェントが実行されます。ユーザーは目標を設定し、作業を誘導し、結果を確認します。

ルーチンワークの場合は、プロンプトを[自動化](⟦8VXT⟧)として保存します。スケジュールに従ってローカルで実行するか、クラウド自動化 ⟦2Z8X⟧を使用して、コンピューターの電源がオフの間も継続するスケジュールまたはイベントトリガーによるリポジトリの作業を行います。定期的な作業を有効にする前に、手動実行を確認してください。

特定の編集を行うには、コードから離れることなく[インラインチャット](⟦RW8F⟧)を使用します。特定のタスクの機能を比較するには、[AI機能の早見表](⟦45CF⟧)を使用します。

## モデル、エージェント、およびツールを選択する

最初のエージェントタスクでは、すべてのオプションを設定せずに[クイックスタートを使用します](⟦TZBT⟧)。ニーズの変化に合わせて、以下の選択肢を調整できます。

| 選択肢 | オプション |
|--------|---------|
| **モデル** | GitHub Copilotを通じて[複数のプロバイダーのモデル](⟦RBSC⟧)を選択するか、独自の[APIキー（BYOK）](⟦V36Y⟧)またはサポートされているローカルモデルを使用します。 |
| **エージェントハーネス** | その[ツールとワークフロー](⟦SJ8D⟧)に基づいて、Copilot、Claude、またはCodexから選択します。 |
| **アクセスと課金** | 既存のGitHub Copilotプラン、サポートされているプロバイダーのアカウント、またはAPIキーを使用します。[ハーネスの要件](⟦WQGR⟧)を確認してください。 |
| **カスタマイズ** | [プラグイン](⟦ZTF2⟧)、[プロジェクトの指示](⟦PZQK⟧)、[スキル](⟦KASS⟧)を使用してエージェントを調整します。[Model Context Protocol（MCP）サーバー](⟦S6YZ⟧)を通じて外部ツールを接続します。 |

## インターフェイスやマシンをまたいで継続する

継続性とは、最初からやり直すことなく、サポートされているインターフェイスやマシン間でエージェントの作業を引き継ぐことを意味します。ワークスペースと実行環境がホストに残ったまま、エージェントと対話する場所を選択できます。セッションのサポートや要件は、ハーネスや宛先によって異なります。

| 作業を行いたい場所 | ここから開始 |
|------------------------|------------|
| **Copilotのアプリやデバイス間** | [GitHub環境](⟦BB94⟧) ⟦TBAS⟧を使用して開発用マシンを登録し、VS Code、GitHub Copilotアプリ、Copilot CLI、GitHub.com、またはGitHub Mobileからエージェントセッションを継続します。利用可能なアクションはクライアントによって異なります。 |
| **管理されたクラウドコンピュート上** | [クラウドセッション](⟦WTZ3⟧) ⟦N7PS⟧を使用すると、自分のマシンをオンラインにしておく必要なく、インタラクティブなエージェント作業を行えます。既存のクラウドセッションを再度開いて会話を続行します。実行はクラウド環境内で行われ、その可用性とライフサイクルはサービスによって管理されます。 |
| **エディターまたはAgentsウィンドウ** | VS CodeでGitHub Copilot、Claude、またはCodexのエージェントハーネスを使用し、[インターフェイス間でセッションを継続します](⟦W6PC⟧)。 |
| **別のマシンのVS Code** | [SSH](⟦WTQR⟧)または[開発トンネル](⟦CEHN⟧)を通じた、VS Code固有のリモート接続を使用します。開発トンネルは、[ブラウザーベースのAgentsウィンドウ](⟦YPJK⟧)もサポートしています。 |

自分のマシンで実行されるセッションの場合は、ホストを実行可能な状態に維持してください。クラウドセッションでは、代わりに管理されたコンピュートを使用します。クラウドでの作業のためにクラウドセッションを開始し、その後そのセッションを再び開いて続行します。

自身のプライベートリポジトリを使用して、[VS Codeでクラウドエージェントタスクを開始し、Copilot CLIでそれを継続します](⟦JFFJ⟧)（実験的機能）。

ツールが実行される場所とモデルがホストされる場所は、個別の選択です。エージェントは、ホストされているプロバイダーにモデルのリクエストを送信しながら、マシン上のファイルを編集できます。

## 制御を維持する

AIは、不正確なコードを生成したり、意図を誤解したりする可能性があります。どの変更をコードベースに反映させるかの最終的な責任はユーザーが負います。

* **統合前にレビューする。** エージェントは、セッションフォルダーまたはワークツリーに直接編集内容を保存できます。変更をコミットまたはマージする前に、[diffをレビューして結果を検証します](⟦SE3P⟧)。
* **アクションを制御して作業をリダイレクトする。** [権限と承認](⟦6GHF⟧)を使用して、どのアクションに確認が必要かを決定します。[リクエストを誘導または停止する](⟦93HE⟧)ことができますが、停止しても完了したアクションや外部サービスへの変更は元に戻りません。
* **分離について理解する。** Gitワークツリーはコードの変更を分離しますが、セキュリティ境界ではありません。エージェントが実行するターミナルコマンドに対するファイルシステムとネットワークの制限については、[プラットフォーム固有のサンドボックスオプション](⟦94S9⟧)を確認してください。

既存のプロジェクトでエージェントを使用する前に、[推奨されるセキュリティ基準](⟦S8BZ⟧)を確認してください。管理されたデバイスでは、組織によって[エンタープライズAIポリシー](⟦F454⟧)を通じて利用可能なエージェント、モデル、およびツールが制限されている場合があります。チャットにエージェントが表示されない場合は、[可用性のトラブルシューティング手順](⟦BSP3⟧)を確認してください。

キーボード、スクリーンリーダー、およびロービジョン向けのワークフローについては、[アクセシブルビューおよびその他のアクセシビリティ機能](⟦EK78⟧)の使用方法を参照してください。

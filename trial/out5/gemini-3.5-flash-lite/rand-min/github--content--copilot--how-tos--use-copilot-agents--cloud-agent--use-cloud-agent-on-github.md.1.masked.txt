## はじめに

GitHub上のさまざまな場所から、GitHub Copilot in the cloudのセッションを開始できます。セッションが実行されると、その進捗を監視したり、フォローアップのプロンプトで指示を与えたり、ブラウザを離れることなく作成されたpull requestの反復作業を行ったりできます。

Copilot in the cloudの詳細については、[AUTOTITLE](/copilot/concepts/copilot-surfaces/copilot-on-github)を参照してください。

また、エージェントアプリを使用して、これらの同じエントリーポイントからパートナー製のエージェントを開始することもできます。詳細については、[AUTOTITLE](/copilot/how-tos/use-copilot-agents/cloud-agent/use-agent-apps)を参照してください。

## Copilot in the cloudセッションを開始する

いくつかの異なるエントリーポイントからセッションを開始できます。

* ⟦37JR⟧ホームペーゼにあるCopilotのホームぺージ（[github.com/copilot](https://github.com/copilot?ref_product=copilot&ref_type=engagement&ref_style=text&utm_source=cloud-gh-docs-home-cta&utm_medium=docs&utm_campaign=universe-2026)）。
* [https://github.com](https://github.com?ref_product=copilot&ref_type=engagement&ref_style=text)にサインインしているときの⟦6AQP⟧GitHubパーソナルダッシュボードまたは⟦4TSV⟧ホームページ。
* リポジトリ内の**⟦FN49⟧ Agents**タブまたはパネル。

デフォルト設定のままプロンプトをすぐに送信することも、プロンプトを送信する前にタスクに合わせてセッションを設定することもできます。

1. プロンプトボックスに、Copilotに実行させたい内容を入力します。希望する成果と制約事項を含めてください。

   > [!TIP]
   > プロンプト内でスラッシュコマンドを使用して、2番目の意見を求めるための `/rubber-duck`、脆弱性をレビューするための `/security-review`、セッションの使用状況情報を表示するための `/usage` など、特定のアクションを実行することもできます。

1. オプションで、**⟦KHWE⟧ Attach**をクリックして、Copilotのリクエストに対する参照情報を提供します。

   **Files and folders**、**Upload from computer**、**Repository**、または**Space**を選択して、リクエストのコンテキストを提供します。

   クラウドサンドボックスセッションでは、コネクタやパーソナルカスタムMCPサーバーを設定することで、サードパーティのソースから追加のコンテキストを提供できます。[AUTOTITLE](/copilot/concepts/customizations/copilot-connectors)および[AUTOTITLE](/copilot/concepts/customizations/mcp#personal-mcp-servers)を参照してください。

1. **Mode**ピッカーを開いて、Copilotとどのように連携したいかを選択します。

   * **Interactive**: （デフォルト）Copilotとステップバイステップで作業します。
   * **Autopilot**: タスクをCopilotに委任して、エンドツーエンドで実行させます。

   同じメニューで、**Tool permissions**を使用して、ツールリクエストの承認方法を制御します。

   * **Assisted**（デフォルト）を選択します。これは安全チェックを使用して、リクエストを承認するかどうか、またはユーザーに確認するかを決定します。
   * **Always ask**を選択して、各リクエストに承認を必須にします。
   * **Allow all**を選択して、すべてのツール、パス、およびURLのリクエストを自動的に承認します。

1. **Models**ピッカーを開き、**Auto**（デフォルト）または特定のモデルを選択します。モデルは、速度とコスト効率、汎用性と知能、または複雑なタスクの能力のいずれかを選択しやすくするために、その長所ごとにグループ化されています。選択したモデルが**Balance**などの設定可能な推論をサポートしている場合は、ドロップダウンメニューを使用して推論レベルを選択することもできます。

1. プロンプトボックスの下にある**Chat**セッションコンテキストピッカーを使用して、セッションのスコープ（個人、組織、またはリポジトリ）を選択します。

   * 検索ボックスにリポジトリ名を入力して、追加するリポジトリを検索します。
   * **Ask anything across repositories**の下で、**Chat**を選択して複数のリポジトリにわたって質問します。デフォルトのスコープは個人のリポジトリです。右側の画像をクリックしてアカウントメニューを開き、組織を選択するか、リポジトリ所有者（ユーザーまたは組織）で検索してスコープを変更します。
   * **Work in a repository**の下で、作業する最近のリポジトリを選択します。リストされるリポジトリは、選択されたスコープを反映しています。

   > [!NOTE]
   > * **Attach**メニュー（前のステップ）からリポジトリを追加すると、プロンプトの参照（コンテキスト資料）が提供されます。一方、ここで**Start a session**の下で選択すると、そのリポジトリがセッションの作業リポジトリ（スコープ）になります。セッションの開始時に、クラウドサンドボックスはそのリポジトリのコピーを取得し、既存の制約の範囲内で、そのコンテンツを操作する権限をCopilotに与えます。
   > * リポジトリがリストされない場合、個人の設定、組織、またはエンタープライズポリシーによってCopilotから除外されている可能性があります。

   オプションで、上記でリポジトリを選択した場合、**main**（またはリストされているデフォルトブランチ名）をクリックして、Copilotが作業コンテキストとして使用し、その中で操作を行うブランチを選択することもできます。

⟦JV26⟧

1. **Send message**をクリックするか、<kbd>Enter</kbd>キーを押してプロンプトを送信し、セッションを開始します。

Copilotはプロンプトに応答し、選択されたコンテキストと環境に基づいてセッションを開始します。要求された場合、Copilotは変更されたファイルのリスト、pull request、生成された成果物（調査計画など）、およびその他の関連する出力を生成します。

### ファイル、issue、またはpull request内からCopilotを開始する

コンテキストページからCopilotとのチャットセッションを開くと、セッションは開いているファイル、issue、またはpull requestのコンテキストで開始されます。

コンテキストパネル自体から新しいエージェントセッションを開始することはできません。Copilotページ、ホームページ、またはエージェントタブから開始する必要があります。

## Copilot cloud agentでセッションを開始する

### エージェントタブまたはパネルからセッションを開始する

エージェントタブやエージェントパネルからセッションを開始できます。「New agent task」フォームが表示されれば、エントリーポイントの違いに関わらず手順は同じです。

⟦3EK4⟧
⟦AW96⟧

### ダッシュボードからセッションを開始する

ダッシュボードのプロンプトボックスから、Copilotに作業の開始を依頼できます。ダッシュボードは、ログインした状態で[https://github.com](https://github.com)にアクセスしたときに表示される、GitHubでのアクティビティのパーソナライズされた概要です。

1. [https://github.com](https://github.com/?ref_product=desktop&ref_type=engagement&ref_style=text)のダッシュボードに移動します。
1. **⟦5X8G⟧ Task**ボタンをクリックします。
1. プロンプトフィールドのドロップダウンメニューを使用して、Copilotに作業させたいリポジトリを選択します。
1. リクエストを説明するプロンプトを入力します。

    たとえば、`Implement a user friendly message for common errors.` と入力します。

    Copilotにpull requestを開かせたい場合は、プロンプトでたとえば `Open a pull request to implement a user friendly message for common errors.` のように依頼できます。

1. オプションで、Copilotのpull requestのベースブランチを選択します。Copilotはこのブランチに基づいて新しいブランチを作成します。
⟦SPVB⟧
1. **⟦67JK⟧ Send now**をクリックするか、<kbd>Return</kbd>キーを押します。

   エージェントタブに移動し、Copilotが新しいセッションを開始します。これはプロンプトボックスの下にある「Recent sessions」リストに表示されます。Copilotはタスクに取り組み、コードの変更をプッシュします。

   > [!NOTE]
   > 機能プレビューで**New Dashboard Experience**を有効にしている場合、新しいセッションはダッシュボードのプロンプトボックスの下にある「Agent sessions」に表示されます。詳細については、[AUTOTITLE](/account-and-profile/reference/personal-dashboard#home-dashboard-view)を参照してください。

### Copilot Chatから開始する

Copilot Chatからタスクを開始すると、新しいCopilot cloud agentセッションには、現在のチャット会話のコンテキストが組み込まれます。つまり、`/task`プロンプトでCopilotにすでに共有した詳細を再度説明する必要はありません。

1. GitHub.comでGitHub Copilot Chatを開きます。
1. `/task`と入力してCopilotにpull requestの作成を依頼し、Copilotに変更させたい内容の詳細を指定します。

   たとえば、`/task Create a pull request to put backticks around file names and variables in output.` と入力します。

1. オプションで、Copilotのpull requestのベースブランチを選択します。Copilotはこのブランチに基づいて新しいブランチを作成し、そのブランチをターゲットとするpull requestに変更をプッシュします。
⟦QSKC⟧
1. **⟦TFH6⟧**をクリックするか、<kbd>Enter</kbd>キーを押します。

   Copilotが新しいセッションを開始し、プロンプトボックスの下のリストに表示されます。Copilotはタスクに取り組み、変更をpull requestにプッシュし、完了するとレビュアーとしてあなたを追加して通知をトリガーします。

## Copilotにissueを割り当てる

issueをCopilotに割り当てることで、Copilotにissueの作業開始を依頼できます。Copilotはタスクの作業を開始し、pull requestを作成し、完了するとあなたにレビューを依頼します。

> [!NOTE]
> この機能はパブリックプレビュー段階であり、変更される可能性があります。

⟦AXHG⟧
⟦TBWS⟧

1. Copilotに割り当てたいissueを開きます。
1. 右側のメニューで**Assignees**をクリックします。

   ![issueの右サイドバーのスクリーンショット。「Assignees」というラベルのヘッダーが濃いオレンジ色で囲まれています。](/assets/images/help/issues/assignee-menu.png)

1. 割り当て先リストから**Copilot**をクリックします。

   ![issueの「Assignees」ウィンドウのスクリーンショット。リストにCopilotが用意されています。](/assets/images/help/copilot/cloud-agent/assign-to-copilot.png)

   追加のオプションが表示されます。

   ![ターゲットリポジトリ、開始ブランチ、カスタムエージェント、および追加の指示のオプションを表示する「Assign to Copilot」ダイアログのスクリーンショット。](/assets/images/help/copilot/cloud-agent/assign-to-copilot-dialog.png)

1. **Optional prompt**フィールドで、Copilotへの具体的なガイダンスを追加できます。Copilotがタスクを理解して完了するのに役立つコンテキスト、制約、または要件を追加します。

   たとえば、使用する特定のコーディングパターンやフレームワーク、テスト要件、コードスタイルの好み、変更すべきまたは変更すべきではないファイルやディレクトリに関する指示を含めることができます。

   ここで提供する詳細に加えて、Copilotはターゲットリポジトリに設定されているカスタム指示を使用します。[AUTOTITLE](/copilot/how-tos/copilot-on-github/customize-copilot/add-custom-instructions/add-repository-instructions)を参照してください。

1. ダイアログのドロップダウンメニューを使用して、Copilotが作業するリポジトリと、そこから分岐するブランチを変更できます。

   **少なくとも**読み取りアクセス権を持つすべてのリポジトリが、リポジトリのドロップダウンメニューに表示されます。ただし、リポジトリを選択できるのは、そのリポジトリに対する書き込みアクセス権があり、**かつ**そのリポジトリでCopilot cloud agentが有効になっている場合のみです。

   issueのソース組織とは異なる組織のリポジトリを選択した場合、またはissueがプライベートリポジトリにあるときにパブリックリポジトリを選択した場合、警告が表示されます。

   リポジトリを指定しない場合、Copilotはissueと同じリポジトリで作業します。ブランチを指定しない場合、Copilotは選択したリポジトリのデフォルトブランチから作業します。

   > [!TIP]
   > Copilotにissueを割り当てると、issueのタイトル、説明、現在存在するコメント、および提供した追加の指示が送信されます。issueを割り当てた後、Copilotはその後にissueに追加されたコメントを認識しないため、それに対して反応しません。詳細情報や元の要件に対する変更がある場合は、Copilotが作成したpull requestにコメントとして追加してください。

⟦VD7Q⟧
⟦WXE9⟧

## 失敗したGitHub Actionsワークフローの実行を修正する

pull requestのブランチでGitHub Actionsのワークフローの実行が失敗したとき、Copilotに調査と失敗の修正を依頼できます。

1. GitHubで、失敗したワークフローの実行ジョブページに移動します。
1. **⟦T432⟧ Fix with Copilot**ボタンをクリックします。

   Copilotは新しいセッションを開始し、失敗の原因を調査し、ブランチに修正をプッシュします。

## pull requestの作業を継続する

既存のpull requestに対する変更やレビューコメントへの対応をCopilotに依頼できます。その後、結果のセッションを追跡し、フォローアップの指示を提供できます。

### Copilotに変更を依頼する

任意のpull requestのコメント内で `@copilot` をメンションして、Copilotに変更を依頼できます。これは、Copilotによって作成されたpull requestや、あなたや他のユーザーが作成したpull requestで機能します。

デフォルトでは、Copilotはpull requestのブランチに直接コミットをプッシュします。代わりに別のpull requestを作成するには、コメントでその旨を説明してください。ブランチをチェックアウトして自分で変更をプッシュすることもできます。

GitHub Webインターフェースからpull requestのコメント（レビューやレビューコメントではない）を送信する際、モデルピッカーでモデルを選択します。Copilotはデフォルトで元のpull requestのモデルを使用します。

### レビューコメントを委任する

レビューコメントを委任して、人間のレビュアーやGitHub CopilotコードレビューからのフィードバックをCopilotに実装させることができます。

1. pull requestで、**Files changed**タブを開きます。
1. Copilotに実装させたい最初のレビューコメントに移動します。
   * 1つのコメントを委任するには、**Fix with Copilot**をクリックします。
   * 複数のコメントを委任するには、**Add to batch**をクリックします。Copilotに作業させたいコメントを追加し続けます。
1. **Manage batch**パネルで、追加の指示を追加し、オプションでモデルピッカーでモデルを選択します。
1. Copilotに変更を適用する方法を選択します。
   * 変更をブランチに直接コミットするには、**⟦ZNEY⟧ Fix and commit**をクリックします。
   * 変更を加えた新しいpull requestをCopilotに作成させるには、ドロップダウンメニューから**Fix and open pull request**をクリックします。

### セッションの追跡と継続

⟦7D3S⟧

コメントに応答してCopilotが新しいセッションを開始すると、コメントに目の絵文字（👀）のリアクションが表示されます。pull requestのタイムラインに「Copilot has started work」イベントが表示されます。

![目の絵文字のリアクションと「Copilot started work」のタイムラインイベントがあるレビューコメントが含まれるpull requestのタイムラインのスクリーンショット。](/assets/images/help/copilot/cloud-agent/comment-to-agent-on-pr.png)

Copilotは同じpull requestでの以前のセッションのコンテキストを記憶しているため、フォローアップのリクエストがより速く、より確実になります。pull requestがカスタムエージェントによって作成された場合、`@copilot`をメンションすると、同じエージェントの使用が継続されます。

## マージコンフリクトを解決する

pull request上のマージコンフリクトを解決するようCopilotに依頼するには、2つの方法があります。

* **「Fix with Copilot」ボタンを使用する**: pull requestにマージコンフリクトがある場合、マージボックスに表示される**Fix with Copilot**ボタンをクリックします。
* **@copilotメンションを使用する**: pull requestのコメント内で `@copilot` をメンションし、コンフリクトを修正するよう依頼します（例：「@copilot resolve the merge conflicts on this PR」）。

Copilotはコンフリクトしている変更を分析し、それらを解決し、ビルド、テスト、およびリンターが引き続き合格することを確認します。その後、マージする前に解決を確認できるようにレビューを依頼します。

## 自動化でCopilotを自動実行する

スケジュールに従って、またはissueが開かれるなどのイベントに応答して、Copilotを自動的に実行する自動化を設定できます。自動化の作成と管理は、リポジトリの**Agents**タブにある**Automations**ペインから行います。詳細については、[AUTOTITLE](/copilot/how-tos/use-copilot-agents/cloud-agent/create-automations)を参照してください。

## Copilotの作業に関するフィードバックを提供する

Copilotのpull requestやコメントにあるフィードバックボタンを使用して、出力を評価します。あなたのフィードバックはCopilotの品質向上に役立ちます。

1. Copilotからのpull requestまたはコメントで、サムズアップ（:+1:）またはサムズダウン（:-1:）ボタンをクリックします。
1. サムズダウンボタンをクリックした場合、オプションで理由を選択してコメントを残し、**Submit feedback**をクリックします。

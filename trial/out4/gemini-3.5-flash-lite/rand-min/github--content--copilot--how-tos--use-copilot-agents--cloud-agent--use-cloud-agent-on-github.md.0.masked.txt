## はじめに

⟦SK43⟧セッションは、⟦VB25⟧上のさまざまな場所から開始できます。セッションの実行後は、ブラウザを開いたまま進行状況を監視したり、追加プロンプトで誘導したり、結果として作成されたpull requestを反復修正したりできます。

⟦PPTR⟧の詳細については、[AUTOTITLE](/copilot/concepts/copilot-surfaces/copilot-on-github)を参照してください。

また、⟦7TCN⟧を使用して、これらの同じエントリーポイントからパートナー構築のエージェントを開始することもできます。詳細については、[AUTOTITLE](/copilot/how-tos/use-copilot-agents/cloud-agent/use-agent-apps)を参照してください。

## ⟦TVGY⟧セッションの開始

いくつかの異なるエントリーポイントからセッションを開始できます。

* [github.com/copilot](https://github.com/copilot?ref_product=copilot&ref_type=engagement&ref_style=text&utm_source=cloud-gh-docs-home-cta&utm_medium=docs&utm_campaign=universe-2026)にある⟦HGSN⟧ ⟦4MAH⟧のホームページ。
* [https://github.com](https://github.com?ref_product=copilot&ref_type=engagement&ref_style=text)にサインインしているときの⟦N96X⟧ ⟦QK7B⟧のパーソナルダッシュボードまたは⟦NCXC⟧のホームページ。
* リポジトリ内の**⟦ZSX9⟧ Agents**タブまたはパネル。

デフォルト設定のまま即座にプロンプトを送信することも、タスクに合わせてセッションを設定してからプロンプトを送信することもできます。

1. プロンプトボックスに、⟦X3ZD⟧に行わせたい内容を記述します。求められる成果物や制約事項を含めてください。

   > [!TIP]
   > また、プロンプト内でスラッシュコマンドを使用して特定の操作を実行することもできます。たとえば、第2の意見を得るための `/rubber-duck`、リポジトリの脆弱性をレビューするための `/security-review`、セッションの使用状況情報を表示するための `/usage` などがあります。

1. オプションで、**⟦Q9WW⟧ Attach**をクリックして、⟦FJF7⟧にリクエストの参照情報を提供します。

   リクエストのコンテキストを提供するために、**Files and folders**、**Upload from computer**、**Repository**、または**Space**を選択します。

   クラウドサンドボックスセッションの場合、コネクタや個人のカスタムMCPサーバーを設定することで、サードパーティソースからの追加コンテキストを提供できます。[AUTOTITLE](/copilot/concepts/customizations/copilot-connectors)および[AUTOTITLE](/copilot/concepts/customizations/mcp#personal-mcp-servers)を参照してください。

1. **Mode**ピッカーを開いて、⟦JCYQ⟧とのコラボレーション方法を選択します。

   * **Interactive**: （デフォルト）⟦5KR8⟧とステップバイステップで作業します。
   * **Autopilot**: タスクを⟦NYJX⟧に委任し、エンドツーエンドで実行させます。

   同じメニューで、**Tool permissions**を使用してツールリクエストの承認方法を制御します。

   * **Assisted**（デフォルト）を選択します。これは、安全チェックを使用してリクエストを承認するかどうか、またはユーザーに確認するかを決定します。
   * **Always ask**を選択して、リクエストごとに承認を必須にします。
   * **Allow all**を選択して、すべてのツール、パス、URLのリクエストを自動的に承認します。

1. **Models**ピッカーを開いて、**Auto**（デフォルト）または特定モデルを選択します。モデルは、速度とコスト効率、汎用性と知性、あるいは複雑なタスクへの適性のいずれかを選択しやすくするために、それぞれの長所ごとにグループ化されています。選択したモデルが**Balance**などの設定可能な推論をサポートしている場合は、ドロップダウンメニューを使用して推論レベルを選択することもできます。

1. プロンプトボックスの下部にある**Chat**セッションコンテキストピッカーを使用して、セッションのスコープ（個人、組織、またはリポジトリ）を選択します。

   * 検索ボックスにリポジトリ名を入力して、追加するリポジトリを検索します。
   * **Ask anything across repositories**の下で、**Chat**を選択して複数のリポジトリにわたって質問します。デフォルトのスコープは個人のリポジトリです。右側の画像をクリックしてアカウントメニューを開き、組織を選択するか、リポジトリ所有者（ユーザーまたは組織）で検索してスコープを変更します。
   * **Work in a repository**の下で、作業対象とする最近のリポジトリを選択します。リストされるリポジトリは、選択したスコープを反映します。

   > [!NOTE]
   > * **Attach**メニュー（前の手順）からリポジトリを追加すると、プロンプトの参照（コンテキスト資料）が提供されます。一方、ここで**Start a session**の下で選択すると、そのリポジトリがセッションの作業用リポジトリ（スコープ）になります。セッションの開始時に、クラウドサンドボックスはそのリポジトリのコピーを作成し、既存の制約の範囲内でそのコンテンツを操作する権限を⟦4NAJ⟧に与えます。
   > * リポジトリがリストに表示されない場合、個人設定、組織、またはエンタープライズポリシーによって⟦V4VB⟧から除外されている可能性があります。

   オプションで、上記でリポジトリを選択した場合、**main**（または表示されているデフォルトブランチ名）をクリックして、⟦FBW9⟧が作業コンテキストとして使用し、その中で操作を行うブランチを選択することもできます。

⟦RPNB⟧

1. **Send message**をクリックするか、<kbd>Enter</kbd>キーを押してプロンプトを送信し、セッションを開始します。

⟦8D7A⟧はプロンプトに応答し、選択されたコンテキストと環境に基づいてセッションを開始します。要求された場合、⟦DG8B⟧は変更されたファイルのリスト、pull request、生成された成果物（調査計画など）、およびその他の関連する出力を生成します。

### ファイル、issue、またはpull request内からの⟦D8Z5⟧の開始

コンテキストページから⟦PTAQ⟧とのチャットセッションを開くと、セッションは開いているファイル、issue、またはpull requestのコンテキストを引き継いで開始されます。

## pull requestでの作業の継続

⟦8JXC⟧に変更を行ったり、既存のpull requestに対するレビューコメントに対処したりするよう依頼できます。その後、結果のセッションを追跡し、後続の指示を提供できます。

### ⟦8K9S⟧への変更の依頼

任意のpull requestのコメントで `@copilot` をメンションして、⟦97B5⟧に変更を依頼できます。これは、⟦VRV6⟧によって作成されたpull requestや、あなたや他の人が作成したpull requestで機能します。

デフォルトでは、⟦GPZX⟧はpull requestブランチに直接コミットをプッシュします。代わりに別のpull requestを作成するには、その旨をコメントに記述します。また、ブランチをチェックアウトして自分で変更をプッシュすることもできます。

⟦EDHP⟧のWebインターフェースからpull requestのコメント（レビューやレビューコメントではない）を送信する場合は、モデルピッカーでモデルを選択します。⟦4RAQ⟧はデフォルトで元のpull requestのモデルを使用します。

### レビューコメントの委任

レビューコメントを委任して、人間のレビュアーや⟦269H⟧からのフィードバックを⟦PQ8D⟧に実装させることができます。

1. pull requestで、**Files changed**タブを開きます。
1. ⟦KNYP⟧に実装させたい最初のレビューコメントに移動します。
   * 1つのコメントを委任するには、**Fix with ⟦MHZ4⟧**をクリックします。
   * 複数のコメントを委任するには、**Add to batch**をクリックします。⟦J2CN⟧に作業させたいコメントを追加し続けます。
1. **Manage batch**パネルで、追加の指示を記述し、オプションでモデルピッカーでモデルを選択します。
1. ⟦8Y3C⟧に変更を適用する方法を選択します。
   * ブランチに変更を直接コミットするには、**⟦WJFJ⟧ Fix and commit**をクリックします。
   * ⟦3NJX⟧に変更を含む新しいpull requestを作成させるには、ドロップダウンメニューから**Fix and open pull request**をクリックします。

## マージコンフリクトの解決

pull requestのマージコンフリクトを解決するように⟦WABQ⟧に依頼するには、2つの方法があります。

* **「Fix with ⟦TAGT⟧」ボタンの使用**: pull requestにマージコンフリクトがある場合、マージボックスに表示される**Fix with ⟦KTZR⟧**ボタンをクリックします。
* **@copilotメンションの使用**: pull requestのコメントで `@copilot` をメンションし、コンフリクトの修正を依頼します（例：「@copilot resolve the merge conflicts on this PR」）。

⟦XBBS⟧は競合する変更を分析し、それらを解決して、ビルド、テスト、およびリンターが引き続き合格することを確認します。その後、マージする前に解決を確認できるようにレビューを要求します。

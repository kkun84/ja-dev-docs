## はじめに

GitHub上のさまざまな場所から、クラウドでの GitHub Copilot セッションを開始できます。セッションが実行されると、ブラウザを離れることなく、その進捗を監視したり、フォローアップのプロンプトで指示を与えたり、結果として作成された pull request に対して反復的な作業を行ったりすることができます。

クラウド上の Copilot の詳細については、[AUTOTITLE](⟦MC7D⟧) をご覧ください。

また、エージェントアプリを使用して、これらの同じエントリーポイントからパートナー構築のエージェントを開始することもできます。詳細については、[AUTOTITLE](⟦ED49⟧) をご覧ください。

## クラウドでの Copilot セッションの開始

いくつかの異なるエントリーポイントからセッションを開始できます。

* [github.com/copilot](⟦GRSC⟧) にある Copilot ⟦SK43⟧ ホームページ。
* [https://github.com](⟦CV8X⟧) にサインインしているときの、⟦VB25⟧ GitHub 個人ダッシュボードまたは ⟦PPTR⟧ ホームページ。
* リポジトリ内の **⟦7TCN⟧ Agents** タブまたはパネル。

デフォルト設定のまますぐにプロンプトを送信することも、プロンプトを送信する前にタスクに合わせてセッションを設定することもできます。

1. プロンプトボックスに、Copilot に実行させたい内容を入力します。希望する結果と制約事項を含めてください。

   > [!TIP]
   > プロンプト内でスラッシュコマンドを使用して、セカンドオピニオンを得るための ⟦XAW3⟧、脆弱性がないかリポジトリをレビューするための ⟦M833⟧、セッションの使用状況情報を表示するための ⟦AEGM⟧ などの特定の操作を実行することもできます。

1. オプションで、**⟦TVGY⟧ Attach** をクリックして、リクエストに対する参照情報を Copilot に提供します。

   **Files and folders**、**Upload from computer**、**Repository**、または **Space** を選択して、リクエストのコンテキストを提供します。

   クラウドサンドボックスセッションでは、コネクタや個人のカスタム MCP サーバーを設定することで、サードパーティのソースから追加のコンテキストを提供できます。[AUTOTITLE](⟦ZE93⟧) および [AUTOTITLE](⟦ZPHN⟧) をご覧ください。

1. **Mode** ピッカーを開いて、Copilot とどのように連携するかを選択します。

   * **Interactive**: (デフォルト) Copilot とステップバイステップで作業します。
   * **Autopilot**: エンドツーエンドの実行を Copilot に委任します。

   同じメニューで、**Tool permissions** を使用してツールリクエストの承認方法を制御します。

   * **Assisted** (デフォルト) を選択します。安全性チェックを使用してリクエストを承認するかどうか、またはユーザーに確認するかを決定します。
   * **Always ask** を選択して、各リクエストに承認を必須にします。
   * **Allow all** を選択して、すべてのツール、パス、URL のリクエストを自動的に承認します。

1. **Models** ピッカーを開き、**Auto** (デフォルト) または特定のモデルを選択します。モデルはその長所ごとにグループ化されており、速度とコスト効率、汎用性と知能、または複雑なタスクへの適性のいずれかを選択するのに役立ちます。選択したモデルが **Balance** などの設定可能な推論をサポートしている場合は、ドロップダウンメニューを使用して推論レベルを選択することもできます。

1. プロンプトボックスの下にある **Chat** セッションコンテキストピッカーを使用して、セッションのスコープ (個人、組織、またはリポジトリ) を選択します。

   * 検索ボックスにリポジトリ名を入力して、追加するリポジトリを検索します。
   * **Ask anything across repositories** の下にある **Chat** を選択して、複数のリポジトリにわたって質問します。デフォルトのスコープは個人のリポジトリです。右側の画像をクリックしてアカウントメニューを開き、組織を選択するか、リポジトリ所有者 (ユーザーまたは組織のいずれか) で検索してスコープを変更します。
   * **Work in a repository** の下で、作業を行う最近のリポジトリを選択します。リストされるリポジトリは、選択したスコープを反映しています。

   > [!NOTE]
   > * **Attach** メニュー (前のステップ) からリポジトリを追加すると、プロンプトの参照 (コンテキスト素材) が提供されます。一方、ここで **Start a session** の下でリポジトリを選択すると、そのリポジトリがセッションの作業リポジトリ (スコープ) になります。セッションの開始時に、クラウドサンドボックスはリポジトリのコピーを取得し、既存の制約の範囲内でそのコンテンツを操作する権限を Copilot に与えます。
   > * リポジトリがリストに表示されない場合、個人設定、組織、またはエンタープライズポリシーによって Copilot から除外されている可能性があります。

   オプションで、上記のリポジトリを選択した場合、**main** (またはリストされているデフォルトのブランチ名) をクリックして、Copilot が作業コンテキストとして使用し、その中で操作を行うブランチを選択することもできます。

⟦HGSN⟧

1. **Send message** をクリックするか、<kbd>Enter</kbd> キーを押してプロンプトを送信し、セッションを開始します。

Copilot はプロンプトに応答し、選択したコンテキストと環境に基づいてセッションを開始します。要求された場合、Copilot は変更されたファイルのリスト、pull request、生成した成果物 (調査計画など)、およびその他の関連する出力を生成します。

### ファイル、issue、または pull request 内からの Copilot の起動

コンテキストページから Copilot とのチャットセッションを開くと、セッションは、開いているファイル、issue、または pull request のコンテキストから始まります。

コンテキストパネル内から新しいエージェントセッションを開始することはできません。Copilot ページ、ホームページ、またはエージェントタブから開始する必要があります。

## 失敗した GitHub Actions ワークフロー実行の修正

pull request ブランチで GitHub Actions ワークフローの実行が失敗した場合は、Copilot に調査と失敗の修正を依頼できます。

1. GitHub で、失敗したワークフローの実行ジョブページに移動します。
1. **⟦8D7A⟧ Fix with Copilot** ボタンをクリックします。

   Copilot が新しいセッションを開始し、失敗の原因を調査し、ブランチに修正をプッシュします。

## pull request での作業の継続

既存の pull request の変更やレビューコメントへの対応を Copilot に依頼できます。その後、結果として得られるセッションを追跡し、フォローアップの指示を提供できます。

### Copilot に対する変更の依頼

任意の pull request のコメントで ⟦GZW7⟧ をメンションして、Copilot に変更を依頼できます。これは、Copilot が作成した pull request や、あなたや他の人が作成した pull request で機能します。

デフォルトでは、Copilot はコミットを pull request ブランチに直接プッシュします。代わりに個別の pull request を作成するには、コメントでその旨を説明してください。自分でブランチをチェックアウトして変更をプッシュすることもできます。

GitHub Web インターフェースから pull request のコメント (レビューやレビューコメントではない) を送信する場合は、モデルピッカーでモデルを選択します。Copilot はデフォルトで元の pull request のモデルを使用します。

### レビューコメントの委任

レビューコメントを委任して、人間のレビュアーや GitHub Copilot コードレビューからのフィードバックを Copilot に実装させることができます。

1. pull request で **Files changed** タブを開きます。
1. Copilot に実装させたい最初のレビューコメントに移動します。
   * 1つのコメントを委任するには、**Fix with Copilot** をクリックします。
   * 複数のコメントを委任するには、**Add to batch** をクリックします。Copilot に作業させたいコメントを追加し続けます。
1. **Manage batch** パネルで、追加の指示を追加し、必要に応じてモデルピッカーでモデルを選択します。
1. Copilot に変更を適用する方法を選択します。
   * 変更をブランチに直接コミットするには、**⟦DG8B⟧ Fix and commit** をクリックします。
   * Copilot に変更を加えた新しい pull request を作成させるには、ドロップダウンメニューから **Fix and open pull request** をクリックします。

### セッションの追跡と継続

コメントへの応答として Copilot が新しいセッションを開始すると、コメントに目が描かれた絵文字 (👀) のリアクションが表示されます。「Copilot has started work」イベントが pull request のタイムラインに表示されます。

Copilot は同じ pull request での以前のセッションのコンテキストを記憶しているため、フォローアップのリクエストがより速く、より確実になります。カスタムエージェントによって pull request が作成された場合、⟦N9H8⟧ をメンションすると、その同じエージェントの使用が継続されます。

## マージ競合の解決

pull request のマージ競合を解決するように Copilot に依頼するには、次の2つの方法があります。

* **「Fix with Copilot」ボタンの使用**: pull request にマージ競合がある場合は、マージボックスに表示される **Fix with Copilot** ボタンをクリックします。
* **@copilot メンションの使用**: pull request のコメントで ⟦DNX4⟧ をメンションし、競合を修正するように依頼します (例: "@copilot resolve the merge conflicts on this PR.")。

Copilot は競合する変更を分析して解決し、ビルド、テスト、およびリンターが引き続き合格することを確認します。その後、マージする前に解決を確認できるようにレビューを依頼します。

## 自動化による Copilot の自動実行

スケジュールに従って、または issue がオープンされるなどのイベントに応答して、Copilot を自動的に実行するように自動化を設定できます。自動化は、リポジトリの **Agents** タブにある **Automations** ペインから作成および管理できます。詳細については、[AUTOTITLE](⟦NNNQ⟧) をご覧ください。

## Copilot の作業に対するフィードバックの提供

Copilot の pull request とコメントにあるフィードバックボタンを使用して、出力を評価します。フィードバックは Copilot の品質向上に役立ちます。

1. Copilot の pull request またはコメントで、サムズアップ (:+1:) またはサムズダウン (:-1:) ボタンをクリックします。
1. サムズダウンボタンをクリックした場合は、オプションで理由を選択してコメントを残し、**Submit feedback** をクリックします。

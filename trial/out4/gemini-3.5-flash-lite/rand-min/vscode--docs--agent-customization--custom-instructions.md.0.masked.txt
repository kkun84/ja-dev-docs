# ⟦BKVW⟧ でカスタム指示を使用する

カスタム指示は、コードの追加先、使用するライブラリ、実行するテストなど、プロジェクトに関する再利用可能なガイダンスをエージェントに提供します。このガイダンスをすべてのプロンプトで繰り返すのではなく、Markdownファイルに保存し、ソース管理を通じてプロジェクトの指示を共有します。

エージェントが繰り返し見落としている1つの規約から始めます。[エージェントカスタマイズエディター](/docs/agent-customization/overview.md#agent-customizations-editor)で指示を作成し、さらにターゲットを絞ったガイダンスを追加する前に、新しいチャットでその効果をテストします。サポートされている場所、ファイルの構文、設定については、[カスタム指示リファレンス](/docs/agents/reference/custom-instructions-reference.md)を参照してください。

指示はモデルをガイドするものであり、準拠を保証したり、テスト、コードレビュー、セキュリティ制御を置き換えたりするものではありません。入力時の[インラインサジェスチョン](/docs/editing/ai-powered-suggestions.md)には適用されません。

## プロジェクト指示の概要

リポジトリのルートを開き、使用する予定の[エージェントハーネスを選択します](/docs/agents/run/agent-harnesses.md#select-a-harness)。ハーネスによって、どの指示ファイルが読み取られるかが決まります。たとえば、⟦GZ4H⟧ セッションで Claude モデルを選択しても、Claude ハーネスには切り替わりません。

最初のセットアップでは、テストセッションが未コミットの指示にアクセスできるようにするため、新しいワークツリーではなく現在のフォルダで作業します。

### プロジェクト指示の作成

1. コマンドパレット（`kb(workbench.action.showCommands)`）から **Chat: Open Customizations** を実行してエージェントカスタマイズエディターを開き、**Instructions** タブを選択します。

1. プロジェクト指示ファイルを追加するには、**Workspace** の横にある `+` を選択し、`AGENTS.md` や `CLAUDE.md` など、ハーネス向けに提供されているプロジェクト指示ファイルを選択します。エディターによってワークスペース内にファイルが作成されるか、既存のファイルが開きます。

   リポジトリにすでにプロジェクト指示ファイルがある場合は、競合するコピーを作成するのではなく、そのファイルを開いてください。

1. 繰り返されている問題に対処するいくつかの具体的なルールを追加します。たとえば、Node.js APIプロジェクトでは次のような指示を使用できます。パスとテストコマンドは、リポジトリで機能するものに置き換えてください。

   ⟦P444⟧

1. ファイルを保存します。これらのプロジェクト指示ファイルにフロントマターは必要ありません。

#### ファイルを直接作成する

エージェントカスタマイズエディター以外でファイルを作成したい場合は、ハーネスでサポートされているプロジェクト指示ファイルを使用してください。以下のパスはリポジトリのルートからの相対パスです。必要に応じて不足しているフォルダを作成してください。

| ハーネス | プロジェクト指示ファイル |
|---------|---------------------------|
| ⟦MYKH⟧ | `.github/copilot-instructions.md` または `AGENTS.md` |
| ⟦624K⟧ | `CLAUDE.md` |
| ⟦ZWWV⟧ | `AGENTS.md` |
| ローカル `feature(local-harness)` | `.github/copilot-instructions.md` または `AGENTS.md` |

ルールを追加し、ファイルを保存して、以下に説明するように検証します。`AGENTS.md` は Codex 専用のファイルではなく、エージェント共通のフォーマットです。1つのファイルを複数のハーネス間で共有する前に、[サポートされているフォーマット](/docs/agents/reference/custom-instructions-reference.md#supported-formats-and-locations)を参照してください。

### 指示の検証

ルールが結果に影響を与える小さなタスクをテストします。最初から最後まで同じハーネスとリポジトリを使用します。

1. コマンドパレット（`kb(workbench.action.showCommands)`）から **Chat: Open Customizations** を実行します。**Instructions** を選択し、ファイルがリストされていることを確認します。これはファイルが検出されるかどうかを確認するものであり、エージェントがルールに従うかどうかを確認するものではありません。
1. 指示を作成した会話のガイダンスにテストが依存しないように、新しいチャットを開始します。
1. プロンプトでルールを繰り返さずに、小さな変更を依頼します。APIの例の場合、プロジェクトの既存のパターンを使用してエンドポイントを追加するようエージェントに依頼します。
1. 応答の **References** セクション（利用可能な場合）で指示ファイルを確認します。詳細が必要な場合は、[エージェントデバッグログでリクエストを調査](/docs/agents/agent-troubleshooting/chat-debug-view.md#instructions-or-a-prompt-file-are-not-applied)します。
1. 変更内容とツールの動作を確認します。例の場合、ハンドラーが追加された場所、データのアクセス方法、エージェントが関連するテストを実行したかどうかを確認します。

結果が目標を満たしている場合は、チームで使用できるように指示ファイルをレビューしてコミットします。満たしていない場合は、ルールを追加する前に[ファイルが検出されたか、含まれたか、従われたかを確認してください](#troubleshoot-instructions)。

適用前後の完全な比較とチームへのロールアウトワークフローについては、[AIコードベースの設定](/docs/agents/guides/customize-copilot-guide.md)に従ってください。

## 指示の適用方法

スコープとアクティベーション（有効化）は、異なる質問に答えるものです。スコープは、ガイダンスを利用できる場所と共有者を決定します。アクティベーションは、そのガイダンスがリクエストにいつ含まれるかを決定します。

| スコープ | 用途 |
|-------|------------|
| ワークスペースまたはリポジトリ | ソース管理を通じてコントリビューターと共有されるプロジェクト規約 |
| ユーザー | ハーネスでサポートされている場所における、プロジェクトをまたいだ個人的な設定 |
| 組織 | サポートされているエクスペリエンス向けに一元管理されたガイダンス |

広く適用されるルールには、プロジェクト指示から始めます。コードベースの一部のみで必要なガイダンスには、ターゲットを絞った指示を使用します。

| アクティベーション | 仕組み |
|------------|--------------|
| プロジェクト全体 | ハーネスには、そのプロジェクト指示ファイルからのガイダンスが含まれます。 |
| ファイルパターン | `.instructions.md` ファイルが `applyTo` を使用するか、Claude ルールファイルが `paths` を使用して、エージェントが処理するファイルと一致させます。 |
| タスクの関連性 | ローカルセッションでは、`description` により、エージェントがタスクの指示ファイルを読み取るかどうかを判断できます。これはパターンマッチングとは別です。 |
| 手動 | 自動検出またはアクティベーションが適切でない場合に、特定のリクエストにガイダンスを添付します。 |

`AGENTS.md` などの指示ファイルは、既存のエージェントにガイダンスを提供します。[カスタムエージェント](/docs/agent-customization/custom-agents.md)を定義するものではありません。コーディング規約やプロジェクトコンテキストではなく、再利用可能な多段階のワークフローの場合は、[エージェントスキル](/docs/agent-customization/agent-skills.md)を検討してください。ワークフローを自分で作成する前に、[カスタマイズマーケットプレイスで既存のスキルを探してください](/docs/agent-customization/agent-skills.md#install-a-skill-from-the-customization-marketplace-preview)。リポジトリ固有のコマンドや規約は、プロジェクト指示に維持してください。

### 1つのリクエストに指示を添付する

1回限りの要件の場合は、共有ルールを作成するのではなく、プロンプトにガイダンスを記述します。

1つのリクエストで既存の指示ファイルを再利用するには、チャット入力で **Add Context**（`+` アイコン）を選択し、リクエストを送信する前にファイルを選択します。

## 効果的な指示の記述

リポジトリ内のすべてを説明するのではなく、エージェントがプロジェクト固有の決定を下すのに役立つルールを記述します。

| 代わりに | 次のように記述する |
|------------|-------|
| 良いテストを書いてください。 | `tests/conftest.py` のフィクスチャを再利用し、テストを変更した後に `python -m pytest <test-file>` を実行してください。 |
| アーキテクチャに従ってください。 | HTTPハンドラーが独立してテスト可能な状態を維持できるよう、データベースアクセスは `src/repositories` 内に留めてください。 |
| スタイルに従ってください。 | エラー文字列を返すのではなく、`src/errors.ts` の既存のエラー型を使用してください。 |

* **ルールを簡潔に保つ。** 各要件に対して短い文を使用し、自明ではない制約については説明します。
* **実行可能な詳細を優先する。** エージェントが使用すべきコマンド、ディレクトリ、ライブラリ、または既存の例を指定します。
* **不要なコンテキストを避ける。** フォーマッターやリンターによって強制されるルールを重複させないでください。プロジェクト全体のファイルから専門的なガイダンスを移動します。
* **コードと一緒に指示を維持する。** ソース管理を通じて変更をレビューし、コマンド、アーキテクチャ、または依存関係が変更されたときにルールを更新します。
* **サポートドキュメントを慎重に参照する。** 相対パスと `/` 区切り文字を使用した Markdown リンクを使用します。リンクは、ドキュメントの内容がモデルに確実に届くことを保証するものではありません。[参照ファイルの動作](/docs/agents/reference/custom-instructions-reference.md#reference-other-files)を確認してください。

### 競合する指示の解決

共有要件は、個人、リポジトリ、組織のガイダンス間で一貫性を保ちます。普遍的な優先順位の順序に依存しないでください。[組み合わせのルールはハーネスによって異なります](/docs/agents/reference/custom-instructions-reference.md#combine-instruction-sources)。

個人の指示で1つのライブラリが要求され、リポジトリで別のライブラリが要求されている場合は、競合する個人のルールを削除するか絞り込みます。補うために別のルールを追加しないでください。競合を解決した後に、新しいチャットで同じ代表的なタスクを繰り返します。

## プロジェクトと個人の指示の管理

エージェントカスタマイズエディターの **Instructions** に戻って、既存の指示を見つけて編集します。個人の指示を追加するには、**User** の横にある `+` を選択します。ハーネスでサポートされている名前と保存場所のプロンプトに従い、ファイルを保存し、そのハーネスを使用した新しいチャットで検証します。

プロジェクトをまたいだ個人的な設定には、ユーザースコープを使用します。チームが求めていない限り、個人の応答設定を共有プロジェクトファイルに記述しないでください。場所と同期の制限については、[ユーザー指示](/docs/agents/reference/custom-instructions-reference.md#user-instructions)を参照してください。

また、関連するエージェント、スキル、ツールとともに、[エージェントプラグイン](/docs/agent-customization/agent-plugins.md#what-plugins-provide)内のルールコンポーネントとして指示を配布することもできます。サポートは、選択したハーネスとプラグインフォーマットによって異なります。クライアント間でバンドルを共有する前に、[プラグインの互換性](/docs/agent-customization/agent-plugins.md#cross-tool-compatibility)を確認してください。

## 指示のトラブルシューティング

ガイダンスを変更する前に、失敗のステージを特定します。

| 観測される現象 | 確認すべき事項 |
|------------------|---------------|
| カスタマイズエディターにファイルがリストされない。 | 選択したハーネス、ファイル名、サポートされている場所、およびセッションが変更を含むフォルダを使用しているかどうかを確認します。 |
| ファイルは検出されたが、タスクに含まれない。 | フロントマターのエラーとアクティベーション条件を確認します。一致するファイルをテストするか、手動で指示を添付します。ローカルの場合は、該当する[検出設定](/docs/agents/reference/custom-instructions-reference.md#local-harness-settings)を確認します。 |
| ファイルが含まれているが、結果がそれに従わない。 | 矛盾しているルールや曖昧なルールがないか確認します。1つのルールを明確にし、新しいチャットでタスクを繰り返して、実際の変更とツールの動作を比較します。 |

応答の **References** セクション（利用可能な場合）は、コンプライアンスではなく包含の確認に役立ちます。詳細な証拠については、[指示の診断](/docs/agents/agent-troubleshooting/chat-debug-view.md#instructions-or-a-prompt-file-are-not-applied)に従ってください。問題を再現する前にロギングを準備します。

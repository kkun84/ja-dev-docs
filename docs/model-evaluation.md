この文書の作成日は2026年11月11日（Asia/Tokyo）です。費用の数字は、同日時点の[翻訳方法の比較と推奨](translation-method.md)の見積もりを使います。訳し方の規則は、[訳し方の指針と用語集（案）](translation-guidelines.md)の決定事項に従います。

## この資料の位置づけ

[翻訳方法の比較と推奨](translation-method.md)には、料金の比較と、モデル選定の大まかな進め方が既にあります。こちらは、その「訳し比べ」を、同じページ、同じ観点、同じ採点表で行うための手順です。

主題は、英語を自然で正確な日本語にできているかどうかです。マークダウンやLiquidが壊れていないかは、別欄で記録します。書式の保全は、訳質の採点には使いません。

DeepLなどの機械翻訳APIと、いわゆる強いモデルを使わない案は、検討中です。決定ではありません。ここでいう強いモデルとは、GPT-6.1 Sol、Claude Sonnet 5.5、Gemini 4 Argon、Claude Opus 5.5、GPT-6 Astraを指します。詳しくは、翻訳方法の文書の[DeepLと強いモデルを使わない案（検討中）](translation-method.md#deeplと強いモデルを使わない案検討中)を参照してください。

## 比べる対象

候補の範囲は、採用する方針によって変わります。どちらを採るかは未決です。

**安価なモデルとPLaMoに限る場合**の候補は、次のとおりです。

- GPT-6 Luna（Batch）
- Claude Haiku 5.5（Batch）
- Gemini 3.5 Flash-Lite（Batch）
- DeepSeek Flash（オフピーク）
- Gemini 3.8 Flash（Batch。2026年内の価格）
- PLaMo 3.1 Prime（API Standard）
- PLaMo 3 Translate（ローカル、またはレンタルGPU）

PLaMo 3 Translateは、0.8B、2B、8B、31Bがあります。PFNの自社評価でGPT-6.1 Sol並みとされているのは31Bです。手元の環境に余裕があれば、8Bと31Bの両方を試す余地があります。試すサイズは、訳し比べの時点で決めます。

**品質の高いモデルも含める場合**は、上記に加えて、GPT-6.1 Sol、Claude Sonnet 5.5、Gemini 4 Argonなどを同じ標本で訳します。強いモデルを一次訳に使うかどうかは、その結果を見てからでも間に合います。

DeepL、Google翻訳、Azure Translatorは、どちらの案でも比較対象に入れない前提で書いています。方針が変われば、そのときに足します。

指示文、用語集、敬体の指定、プレースホルダの退避は、候補のあいだで揃えます。PLaMo 3 Translateだけ、用語集と常体・敬体の指定を専用欄で渡せる点が違います。渡す中身は、ほかのモデルの指示文と同じものにします。

## 固定する標本

初版の20ページをすべて訳しても、費用はほとんど問題になりません。ただし、人が読み比べるには多すぎます。ここでは、初版から6ページを固定の標本とします。一度決めたら、あとの追試でも同じ6ページを使います。モデルを足したときに、条件がずれないようにするためです。

選び方は、次の3点です。

- VS Codeのリリースノート、エージェント周辺の操作説明、GitHub Docsの解説と手順が、偏らず入ること
- 製品名やUIの文言、custom instructions、Agent modeなど、指針で決めた語が実際に出ること
- 公式日本語版で書式や訳文が崩れていたページを、少なくとも2つ含めること


| # | 系統 | 上流パス | 入れる理由 |
| ---: | --- | --- | --- |
| 1 | VS Code | `release-notes/v1_146.md` | 週次リリースの長い記事です。新しい機能名と、短い説明文が混在します |
| 6 | VS Code | `docs/agents/run/agents-window.md` | Agents windowなど、画面名を英語のまま残す操作説明です |
| 11 | VS Code | `docs/agent-customization/custom-instructions.md` | 機能名のcustom instructionsと、一般の「指示」の見分けが問われます |
| 13 | GitHub Docs | `content/copilot/concepts/agent-capabilities/about-agents/about-github-copilot-agents.md` | 概念の解説です。機能名と一般の「エージェント」が入り混じります |
| 14 | GitHub Docs | `content/copilot/how-tos/use-copilot-agents/cloud-agent/use-cloud-agent-on-github.md` | 公式日本語版で語順や太字、手順リストが崩れていた、Webからの主How-toです |
| 18 | GitHub Docs | `content/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/customize-the-agent-environment.md` | 公式日本語版で表やコード、`AUTOTITLE`が崩れていた設定ページです |

番号は、[サイト構成案](site-structure.md#初版スコープ)の初版20ページと同じです。原文のコミットも、同文書の調査時点（`microsoft/vscode-docs@0cc882e`、`github/docs@7c3387d`）に揃えます。あとから上流が動いても、この訳し比べでは同じコミットを使います。

人が通読するのは、原則としてこの6ページです。リントは、訳した範囲の全セグメントにかけます。初版20ページをすべて機械訳して合格率だけ見るのは、費用の余裕があれば足してかまいません。その場合も、人が読む標本はこの6ページのままにします。

これらのページが参照する`data/reusables`や`data/variables`は、本文と同じ条件で訳し、本文と一緒に渡します。文だけ、あるいは段落だけを切って訳すと、ページ内の略語や定義が別の意味に置き換わることがあるためです。

## 評価の観点

観点は、指針で決まった11点と、訳文としての正確さ・自然さに分けます。書式の保全は、参考記録です。

### 人が見る観点（本質）

正確さと自然さは、プログラムでは判定できません。次を人が読みます。

| 観点 | 見るところ | 根拠 |
| --- | --- | --- |
| 正確さ | 原文の意味が保てているか。事実の取り違え、訳抜け、勝手な短縮や補足が無いか | 翻訳の主題そのものです |
| 自然さ | 初めから日本語で書かれたように読めるか。不要な人称、受身の濫用、「〜することができます」などの翻訳調が残っていないか | 指針の「翻訳調を避ける」 |
| 文脈に応じた用語 | 機能名・固有名詞は英語のまま、一般の意味の箇所だけ訳せているか。同じ語を、ページの途中で別の扱いにしていないか | 決定事項の9 |
| 手順の文末 | 手順は「〜します」、注意や必須の操作だけ「〜してください」になっているか | 決定事項の3 |

「文脈に応じた用語」と「手順の文末」は、リントでも粗い検出はできます。ただし、その文が機能名なのか一般の意味なのか、注意文なのか通常の手順なのかは、人が判断します。リントの指摘は手がかりであり、採点の対象にはしません。

### リントで見る観点（決定済みの表記）

次は、指針で既に決まっている表記です。機械で検出できるものは、機械に任せます。

| 観点 | 規則 | 根拠 |
| --- | --- | --- |
| 文体 | 本文は敬体（です・ます調）。見出しや表の項目、図のキャプションの体言止めは除く | 決定事項の1 |
| 製品名・UI | 英語のまま残し、原文の書式（太字の有無など）を保つ。訳の側で角括弧や太字を足さない | 決定事項の2、5 |
| pull requestとissue | 概念としても英語のまま。「プルリクエスト」「イシュー」「課題」などにはしない | 決定事項の6 |
| 和欧の空白 | 日本語と英数字のあいだに空白を入れない。リンクの閉じ括弧のあとや、#123のあとは除いてよい | 決定事項の7 |
| UI名への補足 | 英語のUI名に、日本語を括弧で補わない | 決定事項の8 |
| 数字と単位 | 詰めて書く。例: 10GB、3ms、80% | 決定事項の10 |
| カタカナ複合語 | 空白で区切らない。例: アクセストークン | 決定事項の11 |
| 長音 | Microsoftの日本語スタイルガイドに従う。サーバ、ユーザ、フォルダの形は使わない。例外表の語は例外に従う | 決定事項の4 |
| 用語集の禁止形 | 「レポジトリ」など、指針で禁じている形が出ないこと | 用語集 |

リント規則の案は、[リント規則（案）](lint-rules.md)に分けて書きました。採用する項目も、検出の厳しさも、未決です。

### 参考にする観点（書式）

Liquidタグ、見出し、リスト、表、コードブロック、リンク、画像パス、フロントマターの構造が、原文と一致しているかは、リントで記録します。壊れた訳は、正確さや自然さの点から外して扱います。書式の失敗が多いモデルは、運用上の欠点として別途記します。訳質の順位付けには使いません。

## リントで見られること、人が見ること

役割の分け方は、次のとおりです。リントの中身そのものは未決ですので、できることの見立てです。

**リントに任せられること**

- である調の残存、禁止しやすい表現（「〜することができます」「あなたは」「弊社」など）
- 日本語と英数字のあいだの空白、数字と単位のあいだの空白、カタカナ複合語の区切り空白
- UI名への日本語の補足、全角英数字、和文に混じったカンマやピリオド、em dash（—）
- 長音の揺れ、用語集の禁止訳語、原文に無い太字や角括弧
- 原文との構造の一致（Markdown、リンク、コードブロック、Liquid、フロントマター）
- 訳抜けの形跡（英語の文の残留、長さの比が想定から大きく外れること）

**人が読むこと**

- 意味が正確か、日本語として自然か
- 機能名と一般の意味の見分けが、その文で妥当か
- 手順と注意の文末が、趣旨に合っているか
- 略語や、ページ内で定義された語の扱いが、そのページで一貫しているか
- リントが拾えない誤訳、過剰な意訳、原文に無い説明の追加

リントの合格率が高くても、人が読んで不自然なら、そのモデルは一次訳に向きません。逆に、表記の違反が多くても、誤りが機械で直せる種類ばかりなら、運用で補える場合があります。両方を並べて見ます。

## 学習へのデータ提供と引き換えに安く使える仕組み（検討中）

入出力を学習に使わせる代わりに、無料のトークンや割引を得る仕組みの調査です。2026年11月11日（Asia/Tokyo）に、各社の公式文書で確認しました。公式で確認できなかったことは、その旨を書きます。推測では埋めません。使うかどうかは、未決です。

原文は公開されているCC BYの文書ですので、機密性の問題は小さいです。ただし、学習への利用を許すことと、訳文をサイトに載せることは、各社の規約の話になります。末尾に分けて書きます。

分量の目安は、[翻訳方法の比較と推奨](translation-method.md)と同じです。初版20ページは入力が約7.0万トークン、日本語の出力はその約1.41倍です。指示文を足すと、入出力を合わせておおよそ20万トークンになります。全文は入力が約791万トークン、出力が約1,120万トークンで、指示文を足すとさらに増えます。以下の「足りるか」は、この目安で見ています。

### いま確認できたもの

#### OpenAI（complimentary tokens）

出典: [Sharing feedback, evaluation and fine-tuning data, and API inputs and outputs with OpenAI](https://help.openai.com/en/articles/10306912-sharing-feedback-evaluation-and-fine-tuning-data-and-api-inputs-and-outputs-with-openai)（確認日は2026年11月11日）。利用枠の区分は、[Rate limits](https://developers.openai.com/api/docs/guides/rate-limits)のUsage tiersです。

Business向けの製品とAPIでは、入出力を学習に使うことは既定ではありません。組織のオーナーが、データ共有の設定で、入出力の共有を有効にできます。対象は組織全体か、選んだプロジェクトです。あとから解除できます。Zero Data Retentionを有効にしているアカウントと、Enterpriseは、この入出力の共有には参加できません。共有するデータに、機微な情報や社外秘を含めないよう求められています。また、OpenAIがそれを処理・利用する適切な権限が、こちらにあることを確認するよう求められています。

一部の組織は、共有したトラフィックに対して、日ごとの無料トークン（complimentary tokens）を受けられます。対象かどうかは、[データ共有の設定ページ](https://platform.openai.com/account/data-sharing)に、「You're eligible for free daily usage on traffic shared with OpenAI」と出るかどうかで分かります。出なければ、その時点では対象外です。対象の組織が共有を有効にすると、「You're enrolled for complimentary daily tokens」と表示され、下のモデルへの共有トラフィックへ、無料分が自動で当たります。アカウントに残高があることが必要です。OpenAIは、この制度を終えるときは、30日前に知らせると書いています。

無料分は、モデルのグループごとに日次の上限があります。入力と出力を合算し、グループ内のモデルで共有します。毎日0:00（UTC）にリセットされます。1回のリクエストが上限をまたぐと、そのリクエスト全体が通常料金になります。超過分だけではありません。対象外は、ファインチューンしたモデル、ファインチューンの学習、evals、tool useです。

- **Build**（累計のクレジット購入が5ドル以上）: 第1グループは1日あたり最大25万トークン、第2グループは最大250万トークン
- **Launch**（同100ドル以上）と**Grow**（同500ドル以上）: 第1グループは1日あたり最大100万トークン、第2グループは最大1,000万トークン

第1グループには、gpt-6.1-sol、gpt-6-astra、gpt-6-sol、gpt-6-lunaのほか、gpt-5系の一部やoシリーズなどが入ります。いわゆる強いモデルも、こちらに含まれます。第2グループには、gpt-5.6-terra、gpt-5.6-luna、各種のminiやnanoなどが入ります。一覧は、上記のヘルプにあります。gpt-6-lunaは第2グループではなく、第1グループです。

Batch APIがこの無料分に含まれるかは、公式の案内には書かれていません。「共有したトラフィックに自動で当たる」とだけあります。含むとも、含まないとも、ここからは言えません。

初版20ページ（おおよそ20万トークン）は、Buildの第1グループ（25万）でも収まる見込みです。ただし、1回のリクエストが上限をまたがないよう、分割には余裕が要ります。全文（入出力で約1,900万トークン、指示文を足すとさらに増える）を第1グループのモデルで訳すと、LaunchまたはGrowでも1日100万トークンが上限ですので、日をまたいで送る必要があります。Buildの25万では、さらに日数がかかります。第2グループのモデルなら、LaunchまたはGrowでは1日1,000万トークンまでですので、全文でも数日で足りる計算です。対象の組織になれるか、第1グループを使うかは、設定ページと訳し比べの結果次第です。

#### Google Gemini API（無料枠）

出典: [Gemini Developer API pricing](https://ai.google.dev/gemini-api/docs/pricing)、[Gemini API Additional Terms of Service](https://ai.google.dev/gemini-api/terms)（確認日は2026年11月11日）。

Gemini APIの無料枠は、料金ページで「Free input & output tokens」と説明されています。あわせて、「Content used to improve our products」とあります。追加の利用規約では、Google AI Studioと、Gemini APIの未払い枠（unpaid quota）はUnpaid Servicesです。ここへ送った内容と、生成された応答は、Googleの製品や機械学習の技術を提供・改善・開発するために使われます。品質のため、人が入出力を読んで注釈することもあります。その際、GoogleアカウントやAPIキー、Cloudのプロジェクトから切り離す、と書いてあります。機微な情報、機密、個人情報は送らないよう求められています。Cloudの請求先があるプロジェクト経由のAPIはPaid Servicesになり、プロンプトと応答は製品の改善に使われません。

2026年11月11日時点の料金ページでは、Gemini 3.8 FlashとGemini 3.5 Flash-LiteのStandardは、無料枠の入力・出力が「Free of charge」です。Gemini 4 Argonは無料枠では使えません（「Not available」。すべてのトークンが課金される、と注記があります）。Batch API（50%割引）は、料金ページではPaidの説明に含まれています。無料枠でBatchが使えるかは、同ページからは確認できませんでした。1日あたりのトークン上限の数字も、料金ページには出ていません。上限の実数は、利用時点に[Rate limits](https://ai.google.dev/gemini-api/docs/rate-limits)や、Google AI Studioの画面で確認する必要があります。欧州経済領域、スイス、または英国の利用者向けにAPIクライアントを提供する場合は、Paid Servicesだけを使うよう、規約で求められています。本プロジェクトの公開先がそこになるかは、別の話です。

初版20ページは、無料のFlash系で足りる見込みです。全文も、料金としては0円です。ただし、レート制限の実数は公式の料金ページからは分からないため、何日かかるかは、使うときの上限を見てからでないと判断できません。強いモデルのGemini 4 Argonは、この無料枠の対象外です。

#### PLaMo API（Freeプラン）

出典: [PLaMo APIの料金プラン](https://plamo.preferredai.jp/api)、[料金とデータの取り扱い](https://docs.plamo.preferredai.jp/ja/pricing)（確認日は2026年11月11日）。

Freeプランは、PLaMo 3.0 / 3.1 Primeの入力と出力が0円です。登録後すぐに試せます。公式は「利用量・レートリミットに制限あり」と書いています。1日あたりのトークン上限の数字は、料金ページにも[制限事項](https://docs.plamo.preferredai.jp/ja/limit)にも、Freeプラン専用の値としては載っていません。制限事項に出ているのは、リクエスト数の上限（例: `plamo-3.0-prime`はAPIキーごとに毎分100回）などです。

データの扱いは、Freeプランでは、すべての機能で入力と出力を保存し、学習に利用します。ZDRの対象外で、個人情報は入力できません。要配慮個人情報は、プランを問わず入力できません。Standardプランは従量課金（100万トークンあたり入力60円、出力250円）で、入出力を学習に使いません。

初版20ページは、お試しの範囲として現実的です。全文をFreeのまま流せるかは、非公開の利用量上限次第であり、公式の数字だけでは判断できません。強いモデル（GPT-6.1 Solなど）は、このプランの対象ではありません。Batch APIの割引についての記載も、見当たりませんでした。

#### OpenRouter（`:free`バリアント）

出典: [Free Variant](https://openrouter.ai/docs/guides/routing/model-variants/free)、[API Credit & Rate Limits](https://openrouter.ai/docs/api_reference/limits)、[Provider Logging](https://openrouter.ai/docs/guides/privacy/provider-logging)（確認日は2026年11月11日）。

OpenRouterには、モデルIDの末尾に`:free`を付けて、無料のエントリを呼ぶ方法があります。料金はかかりません。その代わり、無料モデルにはリクエスト数の上限があります。生涯のクレジット購入が10未満なら、毎分20回、1日50回です。10以上なら、毎分20回、1日1,000回です（1日分はUTCの日付で数えます）。アカウントの残高が負だと、無料モデルでも拒否されることがあります。

OpenRouter自身の学習方針とは別に、上流のプロバイダが学習するかどうかを、設定で選べます。有料モデルと無料モデルで、設定は分かれています。学習するプロバイダを避ける設定にすると、そのようなプロバイダへはルーティングしません。つまり、これは「OpenRouterに学習させて無料になる」制度ではなく、無料のモデル枠と、上流の学習可否を組み合わせたものです。`:free`に、いわゆる強い商用モデルが入るかは、利用時点のカタログで確認する必要があります。この調査では、カタログの全件は追いませんでした。

初版20ページは、翻訳単位を分けても、1日50回の範囲に収まる見込みです。全文は、1日50回では日数がかかります。1日1,000回まで上げるには、累計で所定のクレジット購入が要ります。Batch APIに相当する扱いは、公式のこの案内には出ていません。

### 確認できなかったもの、または今は使えないもの

**Anthropic。** 商業製品とAPIの入出力は、既定では学習に使われません（[Is my data used for model training?](https://privacy.claude.com/en/articles/7996868-is-my-data-used-for-model-training)）。任意参加の[Development Partner Program](https://support.claude.com/en/articles/11174108-about-the-development-partner-program)は、ファーストパーティのClaude APIによるClaude Codeの入出力だけを対象にし、学習への利用を許すものです。翻訳API一般には当たりません。無料トークンや割引の記載も、同ページにはありません。研究向けのクレジット（AI for Scienceなど）は、データ提供の対価ではなく、対象も研究者に限られます。学習と引き換えにAPIを安くする仕組みは、公式では確認できませんでした。

**xAI。** 2026年11月11日時点の公式FAQ（[Does SpaceXSI train on customers' API requests?](https://docs.x.ai/developers/faq/security)）は、明示の許可なくAPIの入出力を学習に使うことはない、と書いています。既定では、監査のため入出力を30日間保管し、学習には使わず、その後削除します。かつては、データ共有と引き換えに月額クレジットを出す制度があった、という二次の記述や、2025年5月末で終了したというメールの転載はあります。しかし、いまの公式FAQと料金の案内には、その制度の記載は見当たりません。現時点では、使えないものとして扱います。

**Mistral。** [Free mode](https://help.mistral.ai/en/articles/347617-do-you-use-my-user-data-to-train-your-artificial-intelligence-models)では、入力と出力を学習に使う場合がある、と案内時に示され、いつでもオプトアウトできます。ただし公式の[Usage and limits](https://docs.mistral.ai/admin/billing-usage/usage-limits)は、Free modeの月次予算はVibeとStudioをお試しするためのもので、APIアクセスは含まない、と書いています。APIキーの作成とAPIの利用には、課金の有効化と従量課金が必要です。従量課金でも学習のオプトアウトはできますが、学習を許すことの対価としての割引は、公式には書かれていません。APIを無料で使う仕組みとしては、確認できませんでした。

**DeepSeek。** [Open Platform Terms of Service](https://cdn.deepseek.com/policies/en-US/deepseek-open-platform-terms-of-service.html)（2026年4月29日施行）には、出力の権利を利用者へ移転する旨と、個人利用や研究、派生開発、他モデルの学習などへ使える旨があります。一方で、APIの入出力をDeepSeekが学習に使うかどうかと、その対価としての無料枠は、この文書からは確認できませんでした。オフピーク料金はありますが、学習提供の対価ではありません。

ほかに、同種の「学習への提供と引き換えのAPI無料枠」を、この調査の範囲で公式から確認できた事業者はありませんでした。新規登録時の少額クレジットや、スタートアップ向けの審査制クレジットは、学習の対価ではないため、ここには含めません。

### 訳文の公表と、原文のライセンス

原文はCC BYです。出典を示せば、複製や翻案、再配布はライセンス上可能です。一方、各社は「学習や処理に使う適切な権限があること」を、利用者に確認させています。CC BYの許諾が、その確認に足りるかは、この文書では判断しません。機微な情報を含めないこと、個人情報をPLaMoのFreeプランへ入れないことは、公式の求めどおりです。

訳文をサイトに載せる点では、DeepSeekの上記規約は、出力の権利を利用者へ移転すると書いています。Geminiの追加規約は、生成物を公表する前に判断するよう求めています（「Use discretion before relying on, publishing, or otherwise using content provided by the Services」）。OpenAIの上記ヘルプは、共有データの扱いを中心にしており、訳文の公表を禁じる文言は見当たりませんでした。いずれも、使う段階で、その時点の規約を読み直す必要があります。

Geminiの無料枠では、人が入出力を読むことがあります。公開文書であっても、その点は承知したうえで使うことになります。

### この案件での見立て（案）

決定ではありません。確認できた範囲で言えることは、次のとおりです。

- 初版の20ページを、ほぼ無料で試す道は、いまもあります。対象になれば、OpenAIの無料トークン（強いモデルも含む第1グループ）、GeminiのFlash系無料枠、PLaMo APIのFreeプランが、その候補になります。
- 全文を同じ仕組みだけで賄えるかは、制度によります。OpenAIの第1グループには日次上限があります。GeminiのFlash系は料金は0円ですが、レート制限の実数は使うときに確認します。PLaMoのFreeは、利用量の上限が公式には数字で出ていません。Gemini 4 Argonのように、無料枠に無い強いモデルは、この仕組みでは使えません。
- Anthropicと、いまのxAIには、翻訳API向けの同種の仕組みは見当たりません。MistralのFree modeはAPIを含みません。
- 費用そのものは、有料のバッチでも初版は1ドル未満、全文でも安価なモデルなら数ドルから数十ドルです。この仕組みの主眼は、無料で強いモデルを試せることと、全文の費用をさらに下げられるかどうかにあります。採否は、対象になれるか、規約を受け入れられるか、訳し比べの結果を見てからでよいと思います。

## 進め方

次の順を提案します。途中で方針が変わっても、標本と採点表は変えません。

1. 指示文、用語集、退避の仕方を固定する。指針の決定事項を、指示にそのまま書く。
2. 各候補で、固定した6ページ（と、それが参照する再利用片）を訳す。任意で、初版20ページ全体も機械的に訳してよい。
3. 訳文をリントにかけ、表記規則と書式の違反を集計する。書式が壊れたセグメントは、人が読む対象から外し、書式の欄にだけ記録する。
4. 残った訳を、人が同じ順で読む。公式日本語版で崩れていた#14と#18は、必ず通読する。
5. 下の採点表に記入し、正確さ、自然さ、表記の違反、運用の手間を並べて見る。
6. 一次訳のモデルと、リントに通らなかったときの切り替え先を、その結果を材料に選ぶ。選ぶこと自体は、この文書では行いません。

不合格のあとの処理は、方針によって違います。強いモデルを使わない案では、同じ範囲の別モデルへ回すか、人の確認待ちにします。品質の高いモデルを使う案では、上位モデルへ格上げする流れもあります。詳しくは翻訳方法の文書を参照してください。

## 採点表のひな形

候補ごとに1枚使います。人が見る4つの観点は、5段階で点を付けます。5がよい側です。表記と書式は、違反の件数と、人が見た印象を書きます。配点を足して総点にはしません。性格の違う指標を、一つの数字にしないためです。

```text
モデル:
日付:
原文コミット: microsoft/vscode-docs@0cc882e / github/docs@7c3387d
方針の範囲: 安価なモデルとPLaMoのみ / 品質の高いモデルも含む

--- 人が見る点（1は低い、5は高い）---
正確さ:  /5
  誤訳・訳抜けのメモ:
自然さ:  /5
  翻訳調や、読みにくさのメモ:
用語の見分け（機能名と一般の意味）:  /5
  迷った箇所:
手順の文末:  /5
  「してください」の過不足:

ページごとのメモ:
  #1 リリースノート:
  #6 Agents window:
  #11 custom instructions:
  #13 agentsの概要:
  #14 GitHub上のクラウドエージェント:
  #18 エージェント環境の構成:

--- リント（参考）---
表記規則の違反:  件
  内訳（敬体、空白、長音、禁止訳語、UIの書式など）:
書式の違反:  件
  内訳（Liquid、表、コード、リンク、フロントマターなど）:
セグメント合格率:  %

--- 総評 ---
一次訳の候補にするか:
切り替え先にするか:
特記（運用の手間、ライセンス表示、長文の切れ方など）:
```

同じ人が、同じ日に、候補を並べて読むのが望ましいです。先に読んだ訳の印象が、あとの訳に乗らないよう、ページ単位で候補を入れ替えて読む方法もあります。やり方は、実際に読むときに決めます。

## 未決事項

1. **モデルの方針。** 安価なモデルとPLaMoに限るか、品質の高いモデルも含めるか。
2. **一次訳のモデル。** 訳し比べの結果を見て選ぶ。
3. **PLaMoを使う場合のライセンス表示。**
4. **人のレビューの範囲。** 試し訳では6ページを通読します。本番で、全ページを人が読むのか、抜き取りにするのかは、別途決める必要があります。
5. **リントの中身。** どの規則を採用し、どこまでを合格の条件にするか。案は[リント規則（案）](lint-rules.md)にあります。
6. **学習へのデータ提供と引き換えの無料枠を使うか。** 対象になれるか、どの事業者の枠を試すか。使う場合の規約の確認も含みます。
